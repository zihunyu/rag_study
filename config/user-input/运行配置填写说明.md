# 服务启动与真实接口测试配置

本文只说明“缺少后会导致真实服务无法连接或对应接口无法测试”的配置。

## 1. 配置写在哪两个文件？

### 非敏感配置

文件：`config/user-input/project-inputs.yaml`

这里填写：

- 主机地址；
- 端口；
- 数据库名和用户名；
- 第三方 API Base URL；
- 模型名称；
- 是否启用某个服务。

这里不能填写密码、Token 或 API Key。

### 密码和 Token

文件：`config/user-input/.env.user.local`

这里填写：

- MySQL 密码；
- Milvus Token；
- LLM、Embedding、Reranker、MinerU 和 ASR 的 Token；
- RabbitMQ、Redis 的完整连接 URL。

该文件不会提交到版本库，不要发送到聊天中。

## 2. 哪些配置会阻止什么测试？

| 想执行的操作 | 必须配置 | 不需要配置 |
| --- | --- | --- |
| 启动当前 G0 后端并访问健康检查 | 本地路径配置；项目已经提供默认值 | MySQL、Milvus、模型 Token、负责人、预算 |
| 测试真实 MySQL 连接和迁移 | MySQL 地址、端口、库名、用户名、密码 | LLM、Embedding、负责人、预算 |
| 测试文档解析 | MinerU 地址和 Token；自建无 Token 时只需地址 | LLM、MySQL 可使用本地适配器 |
| 测试向量入库和检索 | Embedding 地址、模型名、Token；真实 Milvus 地址/Token或本地向量适配器 | LLM、预算 |
| 测试完整文字问答 | LLM、Embedding、Reranker 的地址、模型名和 Token | ASR |
| 测试音频问答 | 上述文字问答配置 + ASR 地址、模型名和 Token | 负责人、预算 |
| 测试真实后台队列和缓存 | RabbitMQ URL、Redis URL | 业务负责人和保留期限 |

负责人、年度文档量、法律保留、保存天数、预算和评测负责人不会阻止开发服务启动，也不会阻止普通接口测试；它们只影响容量规划、费用保护或生产验收。

## 3. MySQL 配置怎么写？

### 3.1 使用本机真实 MySQL

编辑 `config/user-input/project-inputs.yaml`，找到：

```yaml
infrastructure:
  mysql:
```

填写成：

```yaml
infrastructure:
  mysql:
    provision_mode: native_local
    version: "8.4"
    host: "127.0.0.1"
    port: 3306
    database: "rag_kb"
    username: "rag_app"
    password_env: MYSQL_PASSWORD
    tls_required: false
```

然后编辑 `config/user-input/.env.user.local`：

```dotenv
MYSQL_PASSWORD=你的MySQL密码
```

注意：`password_env: MYSQL_PASSWORD` 的意思是“程序去环境变量中读取密码”，这里不能改成真实密码。

数据库中需要存在：

- 数据库：`rag_kb`；
- 用户：`rag_app`；
- 该用户对 `rag_kb` 拥有建表、查询、插入、更新和删除权限。

可使用下面的命令测试连接，命令会提示你输入密码，不会把密码写在命令行中：

```powershell
mysql -h 127.0.0.1 -P 3306 -u rag_app -p rag_kb
```

### 3.2 暂时不测试真实 MySQL

保留当前配置：

```yaml
provision_mode: python_dev_stub
host: not_applicable
```

此时 `MYSQL_PASSWORD` 可以留空，后端 Stub 仍能启动，但不能把结果算作真实 MySQL 集成测试通过。

## 4. 大语言模型 LLM 配置怎么写？

编辑 `config/user-input/project-inputs.yaml`，找到：

```yaml
ai_services:
  llm:
```

假设第三方平台提供：

- Base URL：`https://api.example.com/v1`
- 模型名：`example-chat-model`
- Token：一串秘密字符

YAML 填写：

```yaml
ai_services:
  llm:
    provider: openai_compatible_third_party
    endpoint: "https://api.example.com/v1"
    model_id: "example-chat-model"
    model_revision: provider_managed
    api_key_env: LLM_API_KEY
    allowed_data_classifications:
      - public
      - internal
      - confidential
    timeout_seconds: 120
    max_concurrency: 10
```

`.env.user.local` 填写：

```dotenv
LLM_API_KEY=你的真实LLM_Token
```

说明：

- `endpoint` 填 Base URL，一般不要写到 `/chat/completions`；
- `model_id` 必须与第三方平台文档完全一致；
- 服务商没有固定版本号时，`model_revision` 填 `provider_managed`；
- `api_key_env` 保持 `LLM_API_KEY`，不要把真实 Token 写进去。

## 5. Embedding 配置怎么写？

Embedding 是向量检索的必需服务。没有 Embedding，不能执行真实文档向量化和语义检索。

编辑 `project-inputs.yaml`：

```yaml
ai_services:
  embedding:
    provider: openai_compatible_third_party
    endpoint: "https://api.example.com/v1"
    model_id: "example-embedding-model"
    model_revision: provider_managed
    api_key_env: EMBEDDING_API_KEY
    dimension: "__FILL_ME__"
    normalize: "__FILL_ME__"
    metric: COSINE
    max_concurrency: 10
    allowed_data_classifications:
      - public
      - internal
      - confidential
```

编辑 `.env.user.local`：

```dotenv
EMBEDDING_API_KEY=你的真实Embedding_Token
```

`dimension` 和 `normalize` 不要求你填写。开发程序必须调用一次 Embedding 服务，根据真实返回向量自动确定维度，并根据模型说明确定是否归一化。维度不能猜。

## 6. Reranker 配置怎么写？

编辑 `project-inputs.yaml`：

```yaml
ai_services:
  reranker:
    provider: openai_compatible_third_party
    endpoint: "https://api.example.com/v1"
    model_id: "example-reranker-model"
    model_revision: provider_managed
    api_key_env: RERANKER_API_KEY
    max_concurrency: 5
    allowed_data_classifications:
      - public
      - internal
      - confidential
```

编辑 `.env.user.local`：

```dotenv
RERANKER_API_KEY=你的真实Reranker_Token
```

如果暂时没有 Reranker，后端应允许以 RRF 排序降级启动；但真实重排序效果测试会跳过并标记未完成。

## 7. MinerU 配置怎么写？

### 7.1 使用 MinerU 官网 API

编辑 `project-inputs.yaml`：

```yaml
ai_services:
  mineru:
    mode: remote_api
    endpoint: "https://mineru.net/api/v4"
    token_env: MINERU_TOKEN
    version: provider_managed
    timeout_seconds: 300
    deployment_strategy: hosted_primary
    self_hosted_endpoint: "http://127.0.0.1:8000"
    hosted_api_endpoint: "https://mineru.net/api/v4"
    hosted_api_enabled: true
```

编辑 `.env.user.local`：

```dotenv
MINERU_TOKEN=你的真实MinerU_Token
```

### 7.2 使用自建 MinerU

编辑 `project-inputs.yaml`：

```yaml
ai_services:
  mineru:
    mode: local
    endpoint: "http://127.0.0.1:8000"
    token_env: MINERU_TOKEN
    version: "安装后的实际版本"
    timeout_seconds: 300
    deployment_strategy: self_hosted_primary
    self_hosted_endpoint: "http://127.0.0.1:8000"
    hosted_api_endpoint: "https://mineru.net/api/v4"
    hosted_api_enabled: false
```

自建服务没有配置鉴权时，`MINERU_TOKEN` 可以留空。启动入口规划为：

```powershell
python run_mineru.py
```

## 8. ASR 音频转写配置怎么写？

编辑 `project-inputs.yaml`，找到 `ai_services.asr`：

```yaml
ai_services:
  asr:
    provider: openai_compatible_third_party
    endpoint: "https://api.example.com/v1"
    model_id: "example-asr-model"
    api_key_env: ASR_API_KEY
```

编辑 `.env.user.local`：

```dotenv
ASR_API_KEY=你的真实ASR_Token
```

音频已进入 R1，因此该配置属于真实音频测试的必填项。

## 9. Milvus 配置怎么写？

如果只测试本地向量适配器，保留：

```yaml
provision_mode: python_embedded_or_stub
uri: "python-local-stub://data/storage/vector"
```

如果已有真实 Milvus 服务，编辑 `project-inputs.yaml`：

```yaml
infrastructure:
  milvus:
    provision_mode: existing_native
    version: "2.6.x"
    uri: "http://你的Milvus地址:19530"
    token_env: MILVUS_TOKEN
    tls_required: false
    collection_prefix: "rag"
```

编辑 `.env.user.local`：

```dotenv
MILVUS_TOKEN=你的真实Milvus_Token
```

没有开启鉴权的 Milvus 可以将 `MILVUS_TOKEN` 留空。Windows 本机没有真实 Milvus 服务时，本地 Stub 仍可用于开发，但不能算作真实 Milvus 验收。

## 10. RabbitMQ 和 Redis 怎么写？

当前使用 Python 本地适配器时，下面变量可以留空：

```dotenv
RABBITMQ_URL=
REDIS_URL=
```

使用真实服务时，在 YAML 中把 `provision_mode` 改为 `native_local` 或 `existing_native`，并在 `.env.user.local` 填写完整 URL：

```dotenv
RABBITMQ_URL=amqp://用户名:密码@127.0.0.1:5672/
REDIS_URL=redis://:密码@127.0.0.1:6379/0
```

## 11. 当前最小必填清单

### 只启动本地 Stub

不需要再填写 MySQL 或模型密钥，直接运行：

```powershell
py -3.10 run_backend.py --check
py -3.10 run_worker.py --once
```

正式工程目标仍是 Python 3.12；Python 3.10 只用于当前 G0 Harness。

### 测试真实文字 RAG

必须准备：

1. `LLM endpoint + model_id + LLM_API_KEY`；
2. `Embedding endpoint + model_id + EMBEDDING_API_KEY`；
3. MinerU 地址和 Token，或可运行的自建 MinerU；
4. MySQL 真实连接配置，或者明确使用本地控制面适配器；
5. Milvus 真实连接配置，或者明确使用本地向量适配器；
6. Reranker 地址、模型和 Token；没有时允许降级，但不能测试真实重排。

### 测试音频 RAG

在文字 RAG 配置之外，还必须准备：

1. `ASR endpoint`；
2. `ASR model_id`；
3. `ASR_API_KEY`。

## 12. 不应阻止开发启动的字段

以下字段即使没有填写，也必须允许后端、Worker、前端和 Stub 测试继续运行：

- 负责人姓名；
- 年度文档增长率；
- 法律保留要求；
- 在线内容、备份和审计保存天数；
- 单次问答、入库和月度预算；
- 评测负责人；
- 生产 HA、WORM、域名和值班信息。

这些字段只能阻止生产发布或相应治理验收，不能阻止本地开发服务启动。
