# 父级上下文与引用来源

搜索命中只携带当前分片的正文。`SearchHit.parent_source` 单独保存已授权父分片的 ID、文档与版本、展示文本、检索文本及定位；父级必须属于同一文档和版本，并通过独立 ACL、密级、有效期与生命周期检查。

为兼容已有搜索客户端，保留 `text`、`generation_context`、`parent_text`、`parent_chunk_id`。前两个字段现在仅包含命中分片的检索文本，不能当作完整模型输入；父级完整来源使用 `parent_source`。

证据层是唯一的上下文组装位置：

- 先按命中顺序分配 `E1…En`，再为父级补充独立证据 ID。
- 每个证据的文本只来自自己的分片和章节信息，并持有自己的 `locator`、权限版本及有效期。
- `source_role` 区分命中与父级上下文，子证据的 `parent_chunk_id` 保留来源关系。共享父级只加入一次；父级已被命中或文本与同文档同版本的命中完全相同时，不重复加入。
- 父级可能包含子级原文，这种来源范围重叠被保留；不会再把父级展示文本和检索文本一起拼到子证据中。

生成器按独立证据 ID 引用事实；验证器仅接收该断言引用的文本。父级独有事实引用子证据时不能借用父级内容通过验证。最终权限复核与引用回源检查均覆盖父证据自己的 chunk ID。回源返回该证据的展示文本及定位，旧证据没有展示文本字段时回退到已有 `text`。

父分片的 `source_spans` 保存所有组成子分片的 ID 和定位。SQLite 与向量索引的控制面投影均保留这些范围，父引用覆盖整个来源范围集合；顶层页码等字段只是兼容已有定位器的起始锚点，不能代表父级全部范围。

旧父投影只记录第一个子分片的位置，无法恢复完整来源范围，因此没有 `source_spans` 的父级不会加入上下文。现有子分片仍可用于检索和回答；通过正常重新分块、索引和发布流程可恢复父级上下文，本修复不自动修改生产索引。历史已保存引用维持原记录，无法凭空补全来源。新检索版本为 `hybrid-search-service:g2-v4`，缓存键随检索版本及证据结构变化，避免复用旧组合上下文的答案。
