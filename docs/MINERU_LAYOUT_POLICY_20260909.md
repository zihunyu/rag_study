# 所有 MinerU 路由统一保留解析结构

2026-09-09。用户要求：所有实际走 MinerU 的文件均先保留 MinerU 的正文与结构，
图片模型仅补充其中的插图、图表，不限定 PDF。

## 原因与修改

- 原先 `VisualDocumentParser` 仅对 PDF、扫描 PDF 执行 MinerU 版面优先逻辑。
  DOC、PPT 可能在 MinerU 解析前被整体渲染，并跳过基础解析；图片上传会直接识别原图。
- 现在按照基础解析器是否提供 `visual_sources` 决定执行路径，不再检查文件类型。
  当前生产模式覆盖 PDF、扫描 PDF、DOC、PPT、图片五条 MinerU 路由。
- 先调用 MinerU，再从其保留的结果 ZIP 读取 `image`、`chart`、`table` 裁图。
  正文、标题及其他解析节点保留；只有对应插图、图表位置的占位节点由复核结果替换。
  文字、公式附带裁图不交给图片模型，没有插图、图表裁图时不调用图片模型。
- MinerU 路径不再执行本地图片提取、覆盖检查或整页渲染，供应商错误原样向上报告。
  本地原生解析器及历史复核快照仍使用各自已有路径。
- 解析修订标识更新为 `visual-document-v6:provider-layout-first`。
