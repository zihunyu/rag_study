## 根因及通用修复

1. **事实正确，但正文漏引或扩大了原事实的范围。** 引用遗漏时只允许给已有文字补已有事实对应的来源。若所有原子事实已核对通过，而正文与这些事实不一致，则逐条保留原事实原文重组正文。相邻、同一组来源的事实放在同一段，使“凭证和序列号”这样的联合条件有完整的段落见证。两种正文修复共用一次尝试。
2. **模型收到补写要求，却再次漏掉条款。** 对可验证的纯文本缺口，保留已有正文，直接追加当前、授权来源中的精确原文及引用；不再让模型重新写一遍同样的事实。无法满足这些条件的图像等路径仍使用原有有界修复流程。
3. **把用户陈述的场景错误地要求成资料中的记录。** 用户明确给出的情况可以作为应用资料规则的条件前提，但不能冒充资料已核实的事实，不能覆盖资料规定，也不能从一个条件推断其他条件全部满足。不确定的提问不能转换成已确认事实。
4. **一份摘录不完整，被误判成合并后仍不完整。** 检查其他实际提供且被引用的来源能否补齐同一主题、同一范围；缺少互补来源时仍拦截。业务限制、真实冲突不会被免除。
5. **会话入口失败只显示笼统提示。** 保留失败阶段、稳定错误码、实际会话轮次编号、可确认的 HTTP 状态和耗时。检索前失败不再伪装成检索后无答案；限流、请求预算、超时、格式错误分别说明。
6. **数字检查提前拒绝，掩盖来源冲突。** Q23 的比较性事实被数字检查拒绝，组合核验链随后提前退出，未进行语义冲突检查。现在对多文件的这类数值拒绝继续执行全池语义检查，但只采纳已完成核验的冲突发现，绝不覆盖原来的数值事实拒绝；权限或安全结构失败仍直接拦截。原失败草稿真实回放一次调用即识别 E1/E2 冲突，原拒绝判定完整保留。

这些规则按事实、来源、范围和条件工作，生产实现没有针对药物名称、医学分类或合成题编号写分支。

所有修复都要重新通过完整事实、引用、候选条件和全证据池冲突检查。原请求截止时间、调用预算、权限与当前版本检查继续生效；失败或超时仍不会发布未经核验的草稿。
