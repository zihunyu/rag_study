# 面向读者的答案整理与核验

2026-09-07，针对“回答像字段清单、同一名称重复出现、没有综合整理”的反馈，调整答案生成与展示流程。

## 原因

原生成提示要求 `answer` 等于所有原子事实用换行拼接，禁止引言、总结和改写。生成适配器丢弃 `answer`，改用 `render_verified_claims()`；问答服务在验证后又重建一次。因此，即使模型曾写出自然段落，最终也只能展示逐行的事实清单。上一轮主要验证检索及事实支持，未充分检查表达质量。

## 现在的流程

1. 模型通读与问题相关的证据，选择重点，合并重复内容，生成阅读用的 Markdown 正文。只输入名称时按简短介绍处理；多条件参数用表格；单一追问直接回答。
2. 同时生成独立的原子事实清单，每条绑定证据 ID。正文可以使用自然指代、合并句子和表格；事实清单为核验保留完整对象及条件，不直接展示。
3. 本地规则检查清单中的数字、来源、冲突，同时检查正文的引用 ID、外链及敏感操作内容。自然语言改写不能仅靠字符串相似度自动通过，必须进入独立模型核验。
4. 独立核验逐条返回对应 `claim_id` 的结论，另外明确返回整篇正文覆盖及段落/表格行引用检查结果。不能合并、跳过、调换事实结论；遗漏条件、交换数值、正文添写事实或错引来源均不应通过。
5. 所有核验和最终来源有效性检查通过后，发布原样的 Markdown 正文，并缓存同一正文。取消、撤回和历史引用失效机制继续生效。

概述默认面向普通读者，生成提示要求省略未被询问的内部 ID、数据存储、安装版本、实例统计和调试记录。用户明确询问实现细节时仍允许回答。内容取舍仍由模型完成，不能保证每次都完全遵守表达偏好，需要持续结合实际提问检查。整理的是相关证据中的信息，不意味着每次读取知识库所有文件或把所有字段写进答案。

## 兼容与实现

- 新生成协议增加 `format: synthesized_markdown`；内部 `DraftAnswer.synthesized` 标记需要整篇正文核验。没有该格式字段的旧测试适配器继续走原来的事实清单模式。
- 新模式必须收到 `answer_check.covered` 和 `answer_check.citations_valid` 的明确布尔结果。缺字段、字符串布尔值、事实数量/标识不匹配均视为接口错误，不放行答案。
- 核验输出预算按事实数量调整，上限仍受配置约束。保持同一次独立核验调用，不额外追加未经核验的“润色”调用。
- 总结只重新组织原文已给出的数值，不顺手生成原文未记载的差值、倍数、均值或百分比。本轮未增加可审计的计算工具，不能用放宽数字核验来支持这些额外推算。
- 生成与核验 revision 已升级，使旧缓存不被当作新格式回答。Redis 缓存保存格式标记，旧缓存缺字段时按旧格式加载。
- `TrustedQAService` 与低成本评测链路均保留通过核验的正文，避免实际产品和评测结果使用不同的渲染逻辑。
- 前端沿用安全 Markdown 渲染，调整正文间距、表格和行内引用样式。行内引用仍打开当前版本的真实来源侧栏。

主要代码：`backend/src/ragkb/adapters/model_http.py`、`application/qa.py`、`adapters/rag_cache.py`、`domain/rag.py`、`evaluation/low_cost_acceptance.py`，以及 `frontend/src/styles/workspace.css`。

回归测试：`backend/tests/test_answer_synthesis.py` 覆盖正文保留、核验缺失/失败、正文与事实清单不一致、伪造引用、外链、逐事实标识、缓存与发布门槛；前端测试覆盖段落/表格渲染及行内引用打开。最新现场结果见 `artifacts/redesign/ANSWER_SYNTHESIS_DELIVERY.md`。

旧会话保留原始回答，刷新页面不会改写它们。要查看新表达方式，请发送新问题或打开新验收会话。本文所述核验不能保证模型永不犯错，来源不全或存在歧义时仍需说明局限。
