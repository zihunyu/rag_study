# Harness：回答相关性与问答耗时

日期：2026-09-09。

## 本轮范围

增加整段回答相关性检查，整理真实慢问答的阶段与调用记录，并针对复测暴露的范围判断、清单修复和引用补全问题进行修复。未关闭条件核验、冲突核验、权限检查或图片复核；未更换模型，未减少证据范围。

## 工作台行为

- 案例表单增加“检查回答相关性与重复附加内容”。新建案例默认勾选，已有案例维持原设置，保存后产生新版本。
- 相关性作为独立检查项，与必须覆盖的事实分开评审。十项都答到了但额外混入另一事项，仍可能验收失败。空答案没有无关内容也不能凭这一项通过，状态、来源及完整性检查继续生效。
- 必要条件、例外、单位、范围说明与合理的不确定性提示不算偏题。指出偏题必须引用实际答案片段，不能凭模型解释虚构问题。
- 辅助评审保留模型来源；管理员和知识库负责人可记录逐项人工复核，未复核不宣布正式通过。相关性不放进“原句在哪一步丢失”的矩阵，也不要求所有标准原句都出现在答案中。
- 每题详情增加“问答耗时与调用明细”。分别显示资料准备、首次生成、首次核验、修复、再次核验、最终权限/引用检查；显示调用排队、网络时间、失败和相同请求再次发送。
- 各大阶段不重复累计嵌套子阶段。并行 HTTP 时长之和不是用户等待时间。旧记录缺少调用阶段或请求身份时显示未记录；不从耗时猜测请求重复。
- 运行列表区分问答时间与含独立验收评审时间。版本比较继续要求案例、来源与评审标准可比；更快但漏答不算提速成果。

## 真实复评与修复

独立模型复评两条旧答案，均发现相关性问题：

- 十项操作清单附加退货期限、退货条件和运费条款。
- 保修与延保答案末尾重复附加两段“仅用于系统测试”的资料声明。

这两项只补评旧答案，没有修改历史问答或伪造新的问答耗时。补评调用预算上限 6 次，实际记录见 `live-results.json`。

初步统一批次适用性规则后，四题真实复测继续暴露问题，失败记录保留：

1. 核验把“有来源引用的完整清单”误解为对现实适用性的承诺，要求补充测试声明。已明确区分资料内的完整性与现实权威性，相关真实适用条件继续检查。
2. 补完条件再重建清单时，格式逻辑把补充声明编号为第 11、12 项。现仅在确认是逐字追加原文的修复中记录原清单边界；补充条件保留正文与引用，放在清单之外。生成器重新生成的答案不沿用不可靠边界。
3. 表格答案的一句含两个来源支持的事实，但只引用一个来源。引用修复此前只处理完全无引用的行，无法补足已有引用的行。现允许只追加缺少的已知来源，不能删除/替换原引用、改变事实、添加未知来源；修改后完整核验。

全部规则通用于文档问答，没有把药物名称、产品答案或具体测试答案写进业务逻辑。

## 后续性能实验顺序

1. 先减少由错误适用性判断与漏引用引起的反复修复，使用本轮逐题证据核对原因。
2. 图片识别/复核按不同图片有界并行；保留每张图的依赖顺序、并发额度、取消、超时及各自来源。使用相同图片与问题，比较输出事实和图关系。
3. 评估完整声明/冲突核验与条件批次并行的收益。先明确失败时额外调用成本和总预算，不能用较少条件换速度。
4. 对相同资料、权限、模型、提示版本测量普通聊天冷/热缓存；任何来源、权限、时效变化都必须使旧结果失效。
5. 将有证据支持的优化放入同配置的原 24 题和新增清单/表格/条件/跨文件案例回归。质量下降、拒答变多或漏答都不能算有效提速。
