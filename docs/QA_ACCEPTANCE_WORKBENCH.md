# 问答验收工作台 v2

面向总管理员和知识库负责人。入口为左侧「问答验收」，每次先选择自己负责的知识库。
普通问答用户不能访问验收 API；负责人只能维护自己负责的知识库。

## 使用流程

1. 新建案例、导入本功能导出的 JSON、在真实问答下点击「加入验收案例」，或从文档原文生成候选题。
2. 主表单填写问题、预期行为和逐项验收要求；每个要点关联文件版本、原文片段及摘录。
   分类、读取范围、多轮历史和引用要求收在高级设置中。清单题可启用条目数、连续编号和重复检查。
   导入和模型生成的案例始终是候选题；核对原文后才能确认并运行。
3. 选择已确认案例、人工复核或辅助语义评审，填写运行名称和模型调用上限。创建运行会保存案例及资料、配置快照，
   点击「开始运行」后才调用问答。每一道题可以读取多份文件。
4. 页面关闭或刷新不终止服务端运行。暂停、服务故障和预算耗尽保留进度，继续时跳过已完成题，
   当前未完成题另建一次尝试。已完成问答但评审中断时，恢复复用持久化的回答及已完成评审批次，
   只检查未完成要点。进程异常退出后，租约到期（最长约 45 秒）自动标为可恢复。
5. 在结果详情检查程序校验、实际回答、检索原文和引用。逐项检查事实、限制、预期拒答行为后，
   每项显示覆盖、遗漏、错误或待复核，以及模型建议、实际回答摘录、原文依据和说明。
   负责人逐项复核并填写说明，确认通过或记录为失败；历次复核人、结论和记录追加保存。
   程序硬检查失败不能直接人工改成通过，应修复后复测。
6. 新建失败题复测或全部重跑，选择另一条运行作基准，比较改善、退化、未完成、待复核和耗时、
   模型调用及 token。按每道题的实际资料范围判断可比性；其他题引用的外库文件不影响本题。
   整轮用量与共同可比案例的累计用量分别显示，后者包含失败重试及恢复前的调用。
   题数减少不能当成成本优化；覆盖下降而耗时缩短，明确提示质量退化。
   比较问答耗时，不把新增评审时间混入问答速度；只有两侧均已复核通过才认可为通过验收的提速。
   案例、本题资料、权限范围、评审方式或评审规则改变时，明确显示不能直接比较。

## 独立评审与候选题生成

- 从已发布且有权读取的文档中分页选择原文片段，设置题数（1～10）与调用预算，然后创建并启动生成任务。
  每次最多选择 20 段、合计 32,000 字符；模型输出的依据必须逐字存在于所选原文中。
  结果可导入为候选题，仍需负责人核对。选定片段并不代表整份文档或整个知识库已被覆盖。
- 新案例最多 30 个要点，每项最多关联 6 段原文。已确认的必答要点必须有有效原文依据。
  一个要点可关联多份文档。旧案例仍可使用；未建立逐项原文关联的要点保留人工复核。
- 辅助评审读取案例要求、绑定原文和实际回答，独立判断语义；不会采用问答系统的“已验证”作为通过依据。
  每批最多 6 项，并按输入大小拆批；逐批持久化。截断、无效格式、无效证据、预算耗尽均保留明确原因。
  回答证据必须是实际回答的原文，资料证据必须来自对应绑定原文。
- 模型建议全部覆盖仍为“待复核”；模型建议遗漏或错误会标出失败，负责人可以对照证据纠正建议并保留记录。
  程序数量检查与语义覆盖分开展示：重复凑到十条、数量正确但条件错误都不能因此通过。

## 功能边界

- 案例与预期要求保存到独立验收表，不进入知识库索引，也不送入生成模型。
- 程序自动检查回答状态、检索/引用范围、必要检索文件、必要引用文件和引用数量。
  还可检查清单数量、原始编号连续性和文字相同的重复项。语义重复由独立评审及负责人复核。
  系统的 `verified=true` 不等于验收通过。模型生成和评审使用当前配置的核验模型，并受统一预算约束；
  最终确认仍由负责人完成。本功能不自动修改代码或调参。
- 正确拒答可以通过；模型限流或执行中断为未完成，不混同答错。
- 一次运行使用当前部署配置，记录模型名、程序内容摘要、检索发布版本和实际问答 revision。
  在外部调整配置后新建运行即可比较。本版不在页面中修改服务商密钥或创建任意模型配置。
- 验收跳过已验证答案缓存，重新执行生成和核验；正常问答的缓存行为保持原样。
- 每次真实 HTTP 模型请求发送前事务预留预算，包括重试、检索模型和历史前置轮。
  超出预算不会继续发送。预留但未收到结果的调用，其用量标为未知。
  已配置单价的调用记录估算费用；无单价或无用量时显示未知，不能计作零成本。
- 多轮案例真实执行前置问题，不使用案例里的参考答案伪造历史。前置轮失败时目标题尚未完成。
- 案例修改递增版本；归档可恢复；运行保存独立快照；复测和人工复核均追加记录。
  资料、程序或权限范围发生变化时不能续跑旧快照，应新建运行；同一用户重新登录可恢复。
- 运行创建人负责启动/恢复，总管理员或当前负责人可以查看结果及请求暂停。
  后台每次模型请求重新检查账号和管理权限，执行租约避免同一运行重复消费。
- 原文读取重新检查当前文件权限与版本。来源失效时隐藏历史正文和证据。
  管理员可进一步展开私有诊断；普通详情不公开未发布草稿或完整模型请求响应。
- 列表第一版最多显示 1,000 道案例及最近 100 次运行；每次最多选择 100 题，调用上限最多 2,000。
  这些是产品限额，不是性能验收结论。

## 部署与数据库

SQLite 沿用项目启动初始化。MySQL 需要先应用新增迁移，然后更新后端：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/migrate_qa_acceptance.py
.\.venv\Scripts\python.exe -X utf8 scripts/migrate_qa_acceptance.py --apply
```

第一条只检查；第二条仅允许本功能的待执行迁移，发现其他待执行项会拒绝混合升级。
v1 的 `acceptance_cases`、`acceptance_case_revisions`、`acceptance_runs`、`acceptance_attempts`、
`acceptance_reviews`、`acceptance_calls` 六张表及五个索引继续使用。
v2 新增 `acceptance_review_details` 保存每次人工复核的逐项记录；其余结构保存到现有 JSON 快照。
迁移记录可重复检查。
原有签署式生产验收凭据及 `real_acceptance` 的含义不变。

## 文档解析验收与内容去向（v3）

在“问答验收 → 文档解析验收”选择文件、版本与代表性页码，点击“并排查看原文件与解析”。
左侧支持原 PDF、图片、文本和 DOCX；其他 Office 格式下载后在原应用中核对。
右侧切换解析与分块，表格可按行列查看，也可展开原始文本。

逐项填写从原文件独立核对的摘录、页码及说明，保存并确认后执行检查。
支持文字、清单条目、表格行、条件与例外。标准不会从解析结果自动填充，修改保存新版本。
一次标准最多 100 项，检查至多 20 个不同页面；没有固定页码的文本/Word/工作表使用逻辑页 1。
只验收选中样本，不把样本通过当成整份文档准确率。

解析检查不调用模型。忽略排版空白及 HTML/Markdown 表格单元格分隔，保留数字、单位、符号和否定词；
表格行不能把不同行的内容拼成正确关系。记录缺失或索引尚未完成时显示“未记录”，不推测为丢失。
每次运行冻结原文件摘要、标准版本、解析版本及实际检查快照。原文件或标准改变时不直接比较。
解析比较的耗时是本地检查耗时，不是解析器速度。

案例要点可关联相应原文件标准。新问答验收会记录实际首次生成输入和初稿，显示
原文件摘录 → 解析 → 分块 → 检索证据 → 实际生成输入 → 初稿 → 最终答案。
后续修复调用不会覆盖首次输入，原文清单直接整理会标明未调用生成模型。
历史运行没有输入记录时显示“未记录”。逐阶段原句检查与最终语义复核分开：
答案改写可能找不到原句，不能只据此断定漏答。

问答版本比较增加内容去向变化和程序检查变化（例如清单编号由失败变为通过）。
来源版本或案例依据改变时保留不可直接比较的提示；不把不同资料下的耗时变化当作提速证明。
v3 新增 `acceptance_parsing_records` 表与一个索引，继续使用本节部署命令执行迁移。
实测、已修复差异及限制见 [v3 交付记录](QA_HARNESS_V3_DELIVERY_20260909.md)。


## 回答相关性与耗时明细

在案例中勾选“检查回答相关性与重复附加内容”，可单独检查整段答案是否混入其他事项或重复附加条款。必要条件、例外、单位和范围仍必须保留。辅助评审的失败项必须能定位到答案原句，人工复核记录与版本比较也包含这一项；旧案例需保存新版本才启用。

每题详情的“问答耗时与调用明细”区分资料准备、生成、核验、修复和再次核验，列出排队、请求耗时、失败及相同请求再次发送。子阶段或并行调用不能重复相加。旧记录缺失的调用阶段或请求身份不推测。问答耗时与独立验收评审耗时分别显示，未正式验收通过不认定无损提速。

详见 [本轮报告](QA_HARNESS_V4_RELEVANCE_PERFORMANCE_20260909.md)。

图片复核现支持不同图片并行，单图仍按识别、独立核验的顺序执行；设置
`OCR_QUERY_PARALLELISM=1` 可退回串行。问答耗时详情的调用阶段增加“逐图识别与核验”。
精确图片缓存继续校验来源、版本、图片字节、问题与配置，仅复用已完整通过的结果。
实验结果、质量回归和仍需处理的问题见 [图片并行实测报告](QA_HARNESS_V5_IMAGE_PARALLEL_20260909.md)。

条件核验支持联合定位多个原有段落，避免将分开写明的规则和例外当作遗漏。
纯条款引用仍核对其实际条件，不再要求答案重复“满足全部条件”等空泛措辞。
同一次请求中只有条件回执出错时，保留已经检查的事实、引用和完整冲突结果，
仅重查异常条件；正文或证据改变后仍完整核验。耗时明细显示“仅重查回执异常的条件”。
修复边界、全部尝试与实际速度比较见 [重复附加与核验返工报告](QA_HARNESS_V6_DUPLICATION_VERIFICATION_20260909.md)。

## 重复运行与引用结构检查（2026-09-10）

创建问答验收时可选每题 1—5 次，预算覆盖全部轮次及重试。恢复定位到具体案例和轮次；仅评审中断时复用该轮已经完成的问答。结果保留每次尝试，分别展示程序检查、模型建议和人工确认通过次数，以及包含恢复前实际处理时间的中位数、最慢值。

比较页单独展示重复结果：回答状态改变、重复次数不同、质量失败和待人工复核时不会显示已证明无损提速。已回答、资料不足、冲突和系统失败分别统计，前面轮次失败不会被最后一轮成功掩盖。

案例表单新增可选引用结构检查，核对正文引用编号及表格每行引用。语义上是否支持事实、条件和单位仍需独立核对；程序检查不代替语义评审或人工确认。

条件核验回执按稳定编号匹配：已逐项验证的结果保留，只重查缺失、重复编号或无效项目。未知编号拒绝；缺少回执不会被当作条件通过。回执乱序本身不导致整批重查。

对于来源绑定不足的回答，系统可尝试补上同一已授权证据池中的来源关联，正文、数字、单位和既有引用保持原样，再执行完整事实与冲突核验。不能支持的事实仍不发布。失败详情区分来源关联补全失败、核验回执无效与资料确实不足。

答案表格最后竖线外的既有引用标记会移入最后一个单元格显示，避免渲染时丢失。验收详情保留原始来源编号，正常问答中的引用仍可点击查看来源。

验收规则v6不要求为纯粹的“资料未提供”单元格编造引用：行名须对应所问字段，其余单元格只能是明确的资料不足说明，答案还须已通过系统核验。数值、混合内容、“不适用”等政策结论仍要求引用。是否真的缺少资料仍由事实及逐项语义复核判断。规则修正不会改写历史失败记录；历史回执重新检查与新发起问答分别保留。

本轮固定验收范围、执行批次及当前结果见 [Harness v7 记录](QA_HARNESS_V7_REGRESSION_20260910.md)。
