# 问答验收工作台 v1

面向总管理员和知识库负责人。入口为左侧「问答验收」，每次先选择自己负责的知识库。
普通问答用户不能访问验收 API；负责人只能维护自己负责的知识库。

## 使用流程

1. 新建案例、导入本功能导出的 JSON，或在真实问答下点击「加入验收案例」。
2. 填写问题、预期行为、必须满足的事实与限制、禁止说法、必要引用和原文依据。
   导入的案例始终是候选题；核对原文后才能确认并运行。
3. 选择已确认案例，填写运行名称和模型调用上限。创建运行会保存案例及资料、配置快照，
   点击「开始运行」后才调用问答。每一道题可以读取多份文件。
4. 页面关闭或刷新不终止服务端运行。暂停、服务故障和预算耗尽保留进度，继续时跳过已完成题，
   当前未完成题另建一次尝试。进程异常退出后，租约到期（最长约 45 秒）自动标为可恢复。
5. 在结果详情检查程序校验、实际回答、检索原文和引用。逐项检查事实、限制、预期拒答行为后，
   填写复核说明，确认通过或记录为失败。程序硬检查失败不能直接人工改成通过，应修复后复测。
6. 新建失败题复测或全部重跑，选择另一条运行作基准，比较改善、退化、未完成、待复核和耗时、
   模型调用及 token。按每道题的实际资料范围判断可比性；其他题引用的外库文件不影响本题。
   整轮用量与共同案例最新完整尝试的用量分别显示，题数减少不能当成成本优化。
   案例、本题资料或权限范围改变时，明确显示不能直接比较。

## 第一版的边界

- 案例与预期要求保存到独立验收表，不进入知识库索引，也不送入生成模型。
- 程序自动检查回答状态、检索/引用范围、必要检索文件、必要引用文件和引用数量。
  事实、条件的语义正确性由负责人对照原文复核；系统的 `verified=true` 不等于验收通过。
  本版没有另外调用 AI 自动打分，也没有自动生成案例、自动修改代码或自动调参。
- 正确拒答可以通过；模型限流或执行中断为未完成，不混同答错。
- 一次运行使用当前部署配置，记录模型名、程序内容摘要、检索发布版本和实际问答 revision。
  在外部调整配置后新建运行即可比较。本版不在页面中修改服务商密钥或创建任意模型配置。
- 验收跳过已验证答案缓存，重新执行生成和核验；正常问答的缓存行为保持原样。
- 每次真实 HTTP 模型请求发送前事务预留预算，包括重试、检索模型和历史前置轮。
  超出预算不会继续发送。预留但未收到结果的调用，其用量标为未知。
  已配置单价的调用记录估算费用；无单价或无用量时显示未知，不能计作零成本。
- 多轮案例真实执行前置问题，不使用案例里的参考答案伪造历史。前置轮失败时目标题尚未完成。
- 案例修改递增版本；归档可恢复；运行保存独立快照；复测和人工复核均追加记录。
  资料、程序或权限范围发生变化时不能续跑旧快照，应新建运行；同一用户重新登录可恢复。
- 运行创建人负责启动/恢复，总管理员或当前负责人可以查看结果及请求暂停。
  后台每次模型请求重新检查账号和管理权限，执行租约避免同一运行重复消费。
- 原文读取重新检查当前文件权限与版本。来源失效时隐藏历史正文和证据。
  管理员可进一步展开私有诊断；普通详情不公开未发布草稿或完整模型请求响应。
- 列表第一版最多显示 1,000 道案例及最近 100 次运行；每次最多选择 100 题，调用上限最多 2,000。
  这些是产品限额，不是性能验收结论。

## 部署与数据库

SQLite 沿用项目启动初始化。MySQL 需要先应用新增迁移，然后更新后端：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/migrate_qa_acceptance.py
.\.venv\Scripts\python.exe -X utf8 scripts/migrate_qa_acceptance.py --apply
```

第一条只检查；第二条仅允许本功能的待执行迁移，发现其他待执行项会拒绝混合升级。
新增 `acceptance_cases`、`acceptance_case_revisions`、`acceptance_runs`、`acceptance_attempts`、
`acceptance_reviews`、`acceptance_calls` 六张表及五个索引。迁移记录可重复检查。
原有签署式生产验收凭据及 `real_acceptance` 的含义不变。

## 接入现有 24 道合成案例

使用真实导入记录中的资料绑定生成两个验收导入文件，不重复上传业务资料：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/export_synthetic_acceptance_cases.py `
  --bindings artifacts/cross-document-qa/live24/browser-results.json `
  --output artifacts/qa-harness-v1
```

正常库 23 题，冲突库 Q23 一题。JSON 导入到验收案例列表；它们不能作为业务文件上传。
外库和草稿继续作为隔离测试的干扰资料，原有历史实测报告保留。

## 验证

新增回归覆盖版本冲突、导入审批状态、真实本地 QA、独立人工复核、事务预算、HTTP 重试计费、
进程恢复与过期执行者隔离、续跑跳过已完成题、配置变化、跨库访问、私有诊断权限、答案缓存绕过、
当前文档权限重新检查，以及重新登录后的快照一致性。前端检查编辑、来源复核、创建/启动分离和
切换知识库时的迟到响应。

真实模型实测见 [首轮 24 题与失败题复测](QA_ACCEPTANCE_V1_LIVE_20260908.md)。
