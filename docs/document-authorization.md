# 文档读取与管理预览

普通阅读统一使用检索投影授权和权威生命周期复核：租户、知识库、ACL scope、
clearance、有效期、SERVING、当前版本和权限修订都必须匹配。搜索、文档详情、
版本列表、分片读取及引用回源共享 `ResourceAuthorizationService`；管理员和维护者
在普通读取接口中同样受这些限制。不可读文档及版本返回 404。

普通版本列表仅返回当前发布版本。分片逐条重新授权，正文来自已授权投影，
保留的历史分片或过期权限投影不会因为同一文档有其他可读分片而获得访问权限。

维护者通过明确的管理预览入口查看草稿、历史版本和复核材料：

| 用途 | GET 路径 |
| --- | --- |
| 管理文档列表 | `/api/v1/spaces/{space_id}/documents/preview` |
| 管理文档详情及 ETag | `/api/v1/documents/{document_id}/preview` |
| 全部版本 | `/api/v1/documents/{document_id}/versions/preview` |
| 指定版本分片 | `/api/v1/document-versions/{version_id}/chunks/preview` |

这些入口要求同租户的 `admin`，或同时具有 `knowledge_maintainer` 角色和目标知识库
`space:{space_id}:manage` scope。预览不能访问已删除文档。质量报告和版本上传等
管理操作也使用这项权限检查。

前端知识库页提供“管理预览”开关；上传处理完成后进入预览以支持复核。
原先依赖普通 GET 接口隐式预览的客户端应迁移到上述路径。

仓储 `list_chunks()` 必须传 `context`，内部管理调用必须显式传 `preview=True`。
仓储只负责投影过滤；所有对外读取还必须通过资源授权服务复核生命周期。

## 问答最终复核与放行边界

问答执行顺序为：生成前复核 → 生成或读取缓存 → 验证器调用前复核 → 验证器调用
→ 渲染已验证声明 → 获取生命周期锁 → 使用最新时间和权限状态做最终复核
→ 签发引用、写入缓存、持久化结果 → 释放锁。缓存命中也走验证和最终复核。
最终复核覆盖完整证据包，包括模型看过但最终没有引用的证据。

运行实例将 `TrustedQAService.response_release_guard` 绑定到同一个生命周期锁，
撤回、删除、权限变更和版本切换也使用该锁。模型生成和验证不持有该锁，
因此管理员可以在模型等待期间完成撤权。

在单个 `RuntimeComponents` 实例内，授权放行决策以持锁的最终复核为顺序点：
如果撤权先完成，则回答无正文、无引用、`verified=false`，不写入答案缓存；
如果放行先通过，则引用、缓存及结果持久化完成后，撤权才进入临界区。
锁覆盖这些存储操作，因此存储延迟也会推迟等待中的撤权操作获取锁。
阶段错误码分别为 `PRE_GENERATION_PERMISSION_RECHECK_FAILED`、
`PRE_VERIFIER_PERMISSION_RECHECK_FAILED` 和 `FINAL_PERMISSION_RECHECK_FAILED`。
缓存策略版本已更新，旧策略产生的缓存不会直接复用。

此边界不涵盖 FastAPI/ASGI 序列化、网络发送或客户端接收，也不跨独立进程、
独立运行实例及绕过服务直接修改数据库的写入。因此它不承诺“撤权响应完成后，
客户端绝不会再收到此前已经放行的数据”。若部署需要该保证，需先明确以应用放行、
服务端发送还是客户端接收为准，并让所有撤权写入与响应发送使用共享的分布式
放行协议，同时处理已在传输中的响应。独立构造 QA 服务时，调用方也必须显式注入
同步边界；默认空上下文只提供权限复核，不提供并发互斥。
