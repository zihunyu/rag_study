# 图片复核并行与问答回归（2026-09-09）

本轮按“先验证质量，再比较速度”的顺序做实验。文档、案例标准和知识库范围保持不变；没有重新解析文档或向知识库上传标准答案。

## 已实施

- 不同图片的“识别 → 独立核验”可同时执行，默认最多 2 张。每张图片内部的顺序和核验条件保持不变。
- `OCR_QUERY_PARALLELISM=1` 可退回串行；实际并发数同时受图片模型、账号并发限制约束。
- 图片来源、裁图完整性、精确缓存和预算分配仍按确定顺序检查；工作线程仅处理已分配任务，结果按原顺序归并。
- 继承取消、总超时、调用预算、诊断及耗时上下文。致命失败停止后续图片，等待在途调用退出，不返回部分结果。
- 保留已有精确图片缓存：同一问题、配置、版本、图片字节及上下文全部匹配时才复用通过核验的结果。失败或未完整覆盖的结果不缓存为可信答案。
- 耗时详情标明“逐图识别与核验”，记录实际图片数、工作线程数和缓存命中；并行子阶段耗时不相加作为用户等待时间。

## 验收边界

本轮识别到的重复附加内容、额外核验耗时与辅助评审稳定性问题均保留，不以一次答对消除历史失败。模型建议与代理检查不等于管理员或知识库负责人的人工签署。版本比较在人工结论未完成时保持质量待确认，不将答案变短、漏答或拒答增加计算为提速收益。
