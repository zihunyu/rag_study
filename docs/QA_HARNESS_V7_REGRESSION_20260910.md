# Harness v7：范围 1—5 实施与回归结果

截至 2026-09-10，本轮五项范围的实现、固定版本对照与本地服务加载已完成。基线和候选 v35 各完成 48 次案例执行；加载后通过侧边栏额外复测 Q18、Q21，两题程序检查通过，仍待负责人确认。**尚未达到全面“无损提速”的目标**：候选调用减少，但整体更慢，局部重复和间歇核验失败仍有记录。

## 结果与判定口径

| 指标 | 基线 | 候选 v35 |
|---|---:|---:|
| 完成的独立案例执行 / 问答步骤 | 48 / 51 | 48 / 51 |
| 原冻结 v5 规则的程序检查通过 | 47/48 | 46/48 |
| 同一 v6 规则离线重核历史回执 | 47/48 | 47/48 |
| 四类代表题辅助语义检查点覆盖 | 59/61 | 61/61 |
| 系统核验失败而未回答 | 0 | 1 |
| 问答总耗时 | 2605.581 秒 | 2953.365 秒 |
| 实际模型 HTTP 调用，含独立验收评审 | 409 | 395 |
| 已报告输入 / 输出 token | 1512290 / 90428 | 1587827 / 88680 |

总耗时增加 **13.35%**，调用减少 **3.42%**。四类题的 61 个检查点是模型辅助意见，程序通过也不等同于人工签署。各版本的 48 次执行均已逐一留存代理核对记录；产品中的管理员、知识库负责人确认状态没有被代签。

两个原始失败的性质不同：

- **Q18 是验收规则误报。** 答案已给出有依据的功率、保修期和起算日期，电压写明资料未提供；旧规则要求这一“未知”表格行也必须附引用。v6 仅对主核验已通过、行名确为用户所问字段、所有值均为明确资料缺失表述的行免除布局引用要求。带数字、混合已知值、未问字段或“不适用”政策事实仍须引用；事实、相关性和编造检查照常执行。这是通用规则，没有写入题号或业务答案。
- **Q21 是实际核验回执失败。** 固定 v35 样本在有界纠正后仍存在 K7/E7 的无效状态或理由，系统没有发布答案。后续页面复测成功，只能证明该次恢复正常，不能抹去原失败或证明间歇问题消失。

v6 对两版共 **96 份已保存回执**使用相同规则重新检查，只有候选 Q18 的表格引用检查从失败变为通过。没有重新调用模型，没有改写答案、耗时、历史数据库或原运行结论。因此旧运行页面仍显示原来的失败数；[离线重核记录](../artifacts/harness-v7/saved-receipts-recheck.json)与原结果分开保存。

## 五项范围的交付

| 范围 | 已实现与实际核对 |
|---|---|
| 1. 固定基线、案例和来源 | 保留 24 题及十项清单、跨页表格、条件例外、跨文件综合四类题；冻结案例修订、来源版本、发布与权限信息、配置及源码；答案缓存关闭 |
| 2. 减少资料不足的无效调用 | 当前可读范围预检；所选文件在实际向量检索和重排前过滤；同次请求中问题及完整证据输入完全相同才复用筛选；完全没有支持所问事实时正确返回资料不足 |
| 3. 改善重复附加和核验返工 | 首稿就近引用，引用齐全时不再重复输出整段关联文本；遗漏或范围错误携带具体拒绝原因重组完整答案；按稳定编号保留有效条件回执，仅重查无效或缺失项；保留全部来源和冲突复核 |
| 4. 支持重复、恢复和比较 | 每题 1—5 次；按案例及轮次恢复；失败尝试和费用保留；中位数、最慢值、回答状态、程序检查、模型意见、人工确认分开显示 |
| 5. 完成固定回归、定位退化 | 两版各 48 次执行已完成；逐一核对事实、清单完整性、条件、单位、引用和隔离；另有页面启动的两道部署复测，单独计费，不混入速度样本 |

没有重新解析、发布或删除知识库资料。MinerU 正文、标题和结构及“仅对相关裁图补充识别”的处理边界保持不变。生产逻辑没有写死药物、设备或测试题答案，案例标准不进入问答模型的业务证据。

保真边界具体包括：

- 证明可读范围为空，必须结合当前发布记录、权限、可读分块及安全水位；数据库错误不能当作资料不足，扫描达到上限则继续正常检索。
- 同次请求的筛选复用核对完整文本、顺序、来源编号、定位、角色和视觉元数据。不能只凭相似问题或摘要复用。
- 条件重组保留事实、数字、单位、否定、附加前提、例外和完整清单；共同要求不能仅放进某一个对象的表格行。
- 补充检索仍保留最多两条不同查询，核验使用完整原始证据池检查冲突。
- 来源绑定修复只允许追加当前已授权来源的引用，正文、数字、单位和已有引用必须原样保留；发现矛盾或无法证明支持则不发布，补全后仍完整核验。
- 条件回执的未知编号、重复编号、缺失项目及状态矛盾仍受校验，不将缺失判定推断成通过，也没有提高重试上限。
- 前端修正表格最后竖线外引用不可见的问题，将既有标号移到最后单元格，不改存储答案或来源。侧边栏已实测旧 Q11 的“工作日 10:00-17:00 [E7]”及对应 D05 原文。

## 准确性、重复与恢复证据

十项清单三次均输出完整 1—10 项并保留引用；跨页表格三次均保留四地金额和“每人每晚”单位。候选四类题共 61/61 个辅助模型检查点覆盖，包括条件例外与跨文件所需期限、资格和起算日期。

两次重点条件题的初稿曾把共同要求仅绑定到标准服务。核验反馈驱动完整重组后纠正范围，最终答案完整，但分别耗时 143.510 秒和 130.032 秒。Q15 初稿附加了原文不支持的订单渠道建议，核验明确拒绝后重组删除，保留取消、退货条件；该题耗时 100.914 秒，其中修复 8.416 秒、修复后核验 22.811 秒。它们证明拦截与修复有效，同时说明首稿质量仍带来成本。

Q13 本次未再出现表后整段重复复述；但以下问题尚未消失：

- CONDITION 的共同条件仍可能同时出现在总说明和标准服务行。
- CROSS 的 30 日期限仍在两个相关表格行重复。
- Q09 仍有少量套话，不能把程序检查通过当作“没有冗余”。
- 三份 v35 实测跨页表格均未触发新来源绑定修复分支。该分支有两份旧失败回执的保真回放及本地测试，不能宣称已经过实际模型触发验证。
- 表格关联的视觉核验仍有 verification_failed 警告；正文事实完整不能证明图像链路已全部通过。
- Q04 有检索降级记录，虽最终事实完整，不能作为健康检索条件下的速度证据。

实际恢复验证中，一份 LIST 问答已经完成，独立验收评审未完成。恢复复用同一个 rag_run_id，保留原 71.764 秒问答回执，新增问答请求为 0；旧失败尝试仍存在。证据见[恢复记录](../artifacts/harness-v7/candidate-v35-review-recovery.json)。

主瓶颈仍是核验、首稿返工及上游异常。候选的 378 次问答 HTTP 事件中，370 次返回 200，4 次返回 502，另 4 次失败；本地账号队列最长仅 0.0267 秒，核验单次请求最长 60.0197 秒。网络计时包含上游模型处理，不能据此把延迟都归因于网络传输。

Q12 一次重点样本同时发生 502 重试和回执格式纠正；Q08 一次重点样本先出现约 60 秒核验请求失败，随后执行条件重试。候选有 3 次答案修复调用，10 次标记在顶层核验恢复路径内的调用，其中 6 次明确为协议纠正、4 次为条件重试。该计数不含底层 HTTP 对同一请求的所有重试，旧基线也未细标全部协议纠正，因此不能据此直接比较“格式错误率”。页面统一用“核验重试”，具体阶段仍可区分。并行请求时长没有重复相加冒充问答墙钟耗时。

有限的顺序运行和上游波动限制了因果判断。这一轮只能支持局部改善与明确退化，**不支持全部问题不损准确度且大幅提速的结论**。
