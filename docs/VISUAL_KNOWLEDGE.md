# 文档图片识别与图片问答

## 使用方式

在文档详情中打开 **原图与识别**：左侧保留原图，右侧展示识别结果，窄屏改为上下排列。可以逐图切换、放大原图、查看提取文字、导出重绘图 SVG。Word、PDF 支持展开原文档；其他格式保留原文件下载。

新上传的含图文档自动走图片处理。旧版本不会静默改写：点击 **重新识别为新版本**，等待任务完成、检查质量，再确认发布。处理失败可在任务中心重试或取消；原图核对未通过的版本不能发布。

**逐图复核不会重新识别其他图片。** 提交“修订这张图”后，新版本只应用所选图片的人工核对结果；其余图片沿用来源版本的识别内容、疑点、审核记录及状态，包括待复核和识别失败。页面显示“沿用 · 需要复核”等标识。这种继承不会调用其他图片的识别、视觉复核或本地 OCR，也不会把待复核内容自动升级为可问答。只有明确选择“仅重试这张图”，才重新识别该图。若原图、所属章节上下文或历史快照不一致，则保持阻止使用并提示主动重试，不自动扩大模型调用范围。新版本的文档解析、分块、索引和发布校验仍按原有流程执行。

问答中的引用可以打开对应版本的原图与识别结果。引用文字可展开阅读，表格保留行列和合并单元格，不显示 HTML 源码。来源撤回、删除或版本失效后，原图链接会重新检查有效性并拒绝继续读取。

## 独立 OCR 配置

本次将本机 `config/.env` 中现有 `LLM_*` 复制成独立的 `OCR_*` 配置。目前 OCR 模型同现有 LLM，为 **gpt-5.5**。后续修改 OCR 的地址、密钥、模型、超时、并发等，不会修改问答模型配置。OCR 不会在缺失配置时自动借用 LLM 密钥。

`config/.env.example` 只提供占位地址、占位密钥和模型名，默认关闭 OCR，没有复制本机真实连接信息。真实 `.env` 保持 Git 忽略。

| 配置 | 用途 |
|---|---|
| `OCR_ENABLED` | 启用文档图片识别 |
| `OCR_BASE_URL`、`OCR_API_KEY`、`OCR_MODEL` | 独立的 OpenAI 兼容视觉模型服务；须支持图片输入和 JSON Schema 结构化输出 |
| `OCR_ALLOW_HTTP` | 是否允许明确配置的 HTTP 服务；默认关闭 |
| `OCR_TIMEOUT_SECONDS`、`OCR_MAX_CONCURRENCY` | 单次调用超时和每个服务进程内的并发限制 |
| `OCR_MAX_OUTPUT_TOKENS` | 当前设为 8192，避免完整图结构被较小输出预算截断 |
| `OCR_TEMPERATURE`、`OCR_TOP_P`、`OCR_PROMPT_REVISION` | 识别采样参数和提示词版本 |
| `OCR_GENERATION_CACHE_TTL_SECONDS` | 重试时复用当前版本已核对结果的时限；模型、提示词版本、原图位置或相邻上下文变化会重新识别 |
| `OCR_MAX_IMAGE_BYTES`、`OCR_MAX_IMAGE_PIXELS` | 单张原图和规范化图片请求的体积上限、像素上限；超过限制明确失败或待复核，不静默丢弃 |
| `OCR_MAX_IMAGES_PER_DOCUMENT` | 单个文档的图片数量上限，默认 100 |
| `OCR_MAX_REPAIR_ATTEMPTS` | 对核对失败结果重新识别的次数，默认 1，上限 2 |
| `OCR_QUERY_RECHECK`、`OCR_QUERY_MAX_IMAGES` | 检索命中图片证据时，针对本轮问题重新查看原图；默认最多 4 张 |
| `OCR_INPUT_COST_PER_MILLION_CNY`、`OCR_OUTPUT_COST_PER_MILLION_CNY` | 按返回 token 用量记录估算费用；需填写真实价格，估算不等于账单 |
| `OCR_ALLOWED_OUTPUT_DOMAINS` | 与 LLM 配置同时复制的兼容字段；当前 OCR 不输出可访问外链，图片仅由本地版本绑定接口提供 |

这些限制不会修改已发布版本的永久识别记录。新一轮重新识别使用新版本和新记录。OCR_MAX_CONCURRENCY 控制单进程处理并发；启用 MODEL_ACCOUNT_LIMIT_ENABLED 后，Redis 进一步协调 API/worker 的账号并发、请求数和 token 预算。复制同一密钥仍共享供应商配额；不同密钥属于同一账号时可用 MODEL_ACCOUNT_GROUP 显式归组。

## 图片处理流程

1. 取得原始图片和真实来源位置。DOCX 记录内部图片部件与正文段落序号；PDF 位图记录页码；PPTX 保存实际幻灯片、标题和部件路径；XLSX 保存工作表、锚定单元格与行号；同一媒体文件在不同页/表出现时分别保留来源。旧 Office、扫描 PDF 沿用现有 MinerU 路由及其原图、页码、bbox。不会编造 Word 页码。
2. 根据可见内容分类，再分别处理。

| 图片类型 | 处理结果 |
|---|---|
| 架构图、流程图、关系图 | 原文转录 + 节点、分组、连线结构；校验后由 Python 确定性编译为 Mermaid |
| 表格 | 行列、表头、单位、空格和合并单元格；作为表格展示，不转 Mermaid |
| 照片 | 可见事实描述与图中文字，不猜测隐藏结构或未标注属性 |
| 统计图 | 标注数字、单位、图例与可见趋势；不把目测曲线估值作为精确数据 |
| 文字截图 | 文字转录 |
| 混合图片 | 一个结果中分别保留图结构、表格和文字，保留跨区域连接 |
| 模糊或类型不明 | 记录问题，等待补充清晰资料或重新识别 |

3. 校验严格结构：字段类型、节点/分组唯一性、分组循环、连线端点、表格覆盖、越界和重叠。模型不直接生成可执行 Mermaid 指令或任意 HTML。
4. 发起一次新的视觉请求，对照原图核对文字、数字、单位、箭头、虚实线、分组、合并单元格与遗漏。大图保留完整视图，并附重叠局部视图。保留逐次候选与核对记录。
5. 核对不通过时有限重试。仍存在不确定内容时，生成可定位的质量问题；候选事实不写进可检索正文，版本不能确认发布。
6. 核对通过的图文和原文上下文进入现有分块、索引与发布流程。图片内容保留版本、位置、原图哈希，删除清理跟踪原图和识别记录。

## 图片如何参与问答

先使用已核对的转录、关系描述、表格和文档上下文检索，再对命中证据所关联的原图进行有数量限制的本轮补查。视觉模型同时对照原图核对与本问题相关的旧识别事实。补查区分支持、无关、无法确认、冲突、核对失败和超出本轮图片预算。除明确支持并再次通过原图核对外，相关图片证据及包含旧图片文字的父块都会排除；后续补充检索也不能将其带回。问答页面解释排除原因，普通文字证据仍可独立回答其能够支持的部分。

一次问题内复用原图核对状态，下一轮重新检查。图片服务异常仍返回可重试的失败，不能退回未经本轮核对的图片文字。修复升级了问答缓存版本，修复前的缓存答案不会直接复用。

最终仍经过已有的“统一组织答案 → 逐项验证 → 验证通过后展示”流程。历史回答、Mermaid 的自动布局、模型推测都不成为新事实。视觉服务异常返回可诊断的失败，不冒充成功识别。

## 接口与存储

- `GET /api/document-versions/{version_id}/visuals`：管理范围内的图片清单、结果和质量状态。
- `GET /api/document-versions/{version_id}/visuals/{asset_id}/image`：管理范围内读取原图。
- `POST /api/document-versions/{version_id}:reparse-visuals`：以 `If-Match` 和 `Idempotency-Key` 创建新版本处理任务。版本条件来自文档 `/preview` 的 `row_version`。
- 已签名的 RAG evidence source 返回 `visuals`；图片链接绑定同一 run/evidence，并再次检查来源有效性。

图片与核对记录保存于现有 artifacts 存储，按版本哈希隔离，登记到现有内容清理记录。三阶段升级新增 visual-ledger.sqlite 保存进度、修订计划、缓存和调用统计，并增量增加 MySQL conversation_turn_options 表保存每轮阅读范围；没有重新建立空库。备份应包含现有 artifacts 目录及其 SQLite 账本。

单图诊断命令（会调用配置的真实 OCR 服务）：

```powershell
.venv/Scripts/python.exe scripts/analyze_image.py image.png --out artifacts/visuals/my-image
```

输出目录必须不存在。保存 `analysis.json`；只有核对通过时才导出 `evidence.md` 和 `diagram-N.mmd`。

## 四项正确性修复（2026-09-07）

- **原文归属**：Word 的文字与图片共享真实段落坐标，图片识别节点插回所在段落；保存章节和图注，邻近上下文不跨章节或表格单元格。识别标准标题和继承大纲级别的自定义标题。未知位置明确保留 `root`，不沿用最后一个章节。PDF/MinerU 按实际页码、位置占位绑定；没有精确章节证据时不推测产品归属。
- **完整表格行**：视觉模型返回真实表头行数和注释；图片中的表格单独形成结构化节点，不额外建立一份扁平的表格文字供检索。位置匹配的 MinerU 旧表格节点由全部识别组件原位替换，避免保留一份无图片关联的旧 OCR。按完整数据行拆块，每块重复多层表头、单位、脚注和适用条件；合并单元格的条件带入所覆盖的行。记录原始表格行范围。完整单行连同表头超出上限时返回 `VISUAL_TABLE_ROW_TOO_LARGE` 并隔离版本，不拆断单元格后入库。
- **排除失败证据**：同一问题中的检索与补查共享图片核对记录。冲突、看不清、未通过核对和预算内未检查的图片内容均不能成为答案依据；父块中的旧识别文字也一并排除。已通过的图片与独立纯文字仍按正常流程选择和验证。
- **图像预处理**：先按 EXIF 校正旋转，再把透明图合成白底 RGB。保留全景，并按原始分辨率连续生成最长 1600 像素、重叠 160 像素的局部视图，覆盖长图末端。原图本身不改写。最多 64 个局部视图，规范化总字节数也受 `OCR_MAX_IMAGE_BYTES` 限制；超限明确说明需要拆图，不静默舍弃尾部。动画需要静态画面。

这些处理适用于所有走图片识别管线的表格和图片，并没有针对某个产品名或某份文档写特例。旧版本的表头字段缺失时使用兼容默认值，已有原图与历史记录保持可读。要让旧文档使用新的章节与分块方式，需要“重新识别为新版本 → 复核 → 发布”；不会在后台改写已有发布索引。

## 三阶段升级的新增操作

- **原图与识别**：查看对象覆盖、逐图阶段、实际耗时和调用量。点击单元格或节点定位独立 OCR 测得的文字框。重名文字、没有可靠坐标的箭头显示整图核对提示。
- **修订这张图**：可改单元格、条件、节点文字和箭头起终点/方向/线型，也可改普通图片转录和描述。填写原因、对照原图确认后生成新版本；保存修订人、时间和前后差异。结构修改会重建文字并清除未更新的自动说明，避免旧识别残留。未修改图片复用已有有效结果。**仅重试这张图** 也会创建新版本。
- **排除相关章节**：先展示完整依赖排除范围，用户确认剩余章节可独立使用后创建新版本。正文、表头、单位、条件、图片和父块一并隔离；后续修订继承已排除范围。全部被排除时无法发布。
- **逐章总结本篇**：问答可选具体问题、逐章总结、跨图/多文档综合，并选择当前库或一份文档。自动方式识别总结请求。先枚举当前有效章节，逐章读取和看图，再使用原文证据统一回答；章节提要不充当事实证据。每张图带真实章节、图注和邻近上下文，单张图只需核对自身贡献，不要求它包含整篇答案。
- **阅读覆盖**：显示已读章节、原始片段、本轮看图数、未覆盖原因。限额、图片冲突、章节提要失败、排除章节、最终未引用章节均会产生缺口提示。轮次与阅读方式/范围持久化，刷新可恢复阅读进度。
- **系统状态**：显示实际识别/复核模型、PP-OCRv4、共享账号限制以及累计 token。未填写单价时费用明确为未知。

新增配置以 `config/.env.example` 为完整清单：`OCR_VERIFY_*` 独立视觉复核；`OCR_LOCAL_CHECK_ENABLED` 本地文字核对；`OCR_RENDER_*` 与 `OCR_SOFFICE_PATH` 页面渲染；`OCR_CROSS_VERSION_CACHE_ENABLED` 跨版本复用；`MODEL_ACCOUNT_*` 共享账号控制；`MODEL_USAGE_ENABLED` 调用账本；`OVERVIEW_*` 逐章读取预算。

当前默认全文预算：最多读取 1200 个原始片段，重新查看 24 张图片，最终证据 18000 个保守估算 token，输出上限 8192 token，总时限 900 秒。超过预算会显示缺口，需要缩小资料范围或调整配置；不会声称无限全文覆盖。普通具体问答仍默认最多重新核对 4 张图。

新增接口：`POST /api/document-versions/{id}:revise-visuals`、`GET /visual-exclusion-preview`、`GET /visual-diff`、`GET /visual-usage`（后三项位于版本路径下）。`POST /api/ask` 和会话发送接口兼容增加 `reading: {mode, document_ids}`；响应增加 `coverage_report`，会话还返回 `reading_progress`。
