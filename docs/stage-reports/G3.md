## 3. WBS-40 可信问答

- Evidence 使用连续 `E1...En`，绑定 Chunk/DocumentVersion、locator、有效期、authority、
  permission revision、授权/current-version；
- EvidencePackage 绑定 tenant/user/run、query time、generation/retrieval/prompt/model revision；
- 六状态 implemented/tested：`answered`、`insufficient_evidence`、`needs_clarification`、
  `conflicting_evidence`、`out_of_scope`、`system_error`；无 `not_authorized` 泄露；
- 默认 runtime 使用 Search-backed EvidenceProvider，沿用 tenant/ACL/lifecycle/时态/代际/watermark；
- generation 使用确定性 buffered Mock；完整上下文在生成前后双重权威复核，任一失败均无答案；
- `/api/v1/ask` 与 `/ask:stream`；verified 前仅 progress，答案只在最终 result；
- 来源引用为随机 opaque ID + HMAC；服务端记录持久化，URL 无可逆内部 ID；
- preview 以当前 principal 再查 tenant/user、expiry/revoked、tombstone、current/version/permission；
- feedback 绑定原 run owner 与 generation/retrieval/prompt/model revisions。

## 4. WBS-50 生命周期、幂等与审计

- SQLite v10 持久 lifecycle record、security transition、deletion tombstone、cleanup outbox、
  append-only audit、lifecycle idempotency、reference token；
- document/version 创建事务内建立 DRAFT；Worker canonical 写入事务转 STAGED；两者均不可 serving；
- reader 仅可见 ACTIVE/visible；maintainer/admin 使用独立管理读取；未知 lifecycle 一律 404；
- publish/rollback 原子同步 lifecycle、documents.current_version_id/row_version 和各版本 publication state；
- `publication_candidates` 持久 generation/projection/watermark/checksum；仅 VALIDATED+STAGED+ready 可发布；
- 发布/回滚执行 SWITCHING、deterministic projection swap、document row-version CAS、ACTIVE；
  任一步失败回滚全部事实，旧 current version 继续服务；
- 同一当前版本使用新 key 再发布为稳定 no-op，不增加 row version/audit；
- ACL 开始即不可见，projection/watermark 未验证 fail-closed；旧 transition 不能覆盖 revoke；
- delete 立即持久 tombstone；document/version/search/ask/preview 检查 serving 可见性；
  upload/job 状态由 owner/maintainer/admin 按管理语义读取，不把 DRAFT 误作 404；
- 重启恢复加载 tombstone，旧 snapshot 不复活；
- local cleanup 按显式 partition+key 血缘逐项删除 original、canonical/parse/media、temp、
  quarantine 与多版本在线内容，逐项验证不存在后才标记完成；不递归删除 audit/legal-hold/backup；
- MySQL/Redis/Zilliz projection 未获授权，outbox 保持 `PENDING_APPROVAL`，API/UI 不能伪造完成；
- SQLite 提交失败强制回滚内存 copy-on-write 快照；状态、audit、outbox、idempotency 同事务；
- audit hash chain 绑定 trace 与 governance revision；
- Idempotency-Key 同请求返回首次稳定响应，不重复 complete；同键异请求 409；
- publish、rollback、ACL、revoke、delete、cleanup 均覆盖重复/冲突/重启。
- 既有文档新版本创建使用独立 upload session、RBAC、If-Match 和幂等 request hash；
  `version_no` 在 SQLite immediate transaction 内递增，旧版本在新版 PROCESSING/失败时继续 serving。

## 5. 身份与 API 语义

- local_single_user principal 使用权威本地 tenant UUID、user、admin/maintainer/reader roles 和 scope tokens；
- OIDC adapter 只接收“已验签 decoder”输出，并校验 issuer、audience、expiry、sub、tenant、roles/groups；
- 中间件生成请求 principal；读者、维护者、管理员分别执行 RBAC；
- 缺 Bearer/无效 claims 为 401，角色不足 403，跨 tenant/resource/preview 404；
- OpenAPI 所有非 health operation 带 BearerAuth JWT security scheme；
- 企业 IdP 未连接，`enterprise_oidc_acceptance=false`。
