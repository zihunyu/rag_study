## 3. 核心实现

### 上传、隔离和恢复

- 客户端文件名禁止路径穿越；服务端隔离路径由随机 upload session ID 生成；
- 大小、SHA-256、扩展名、声明 MIME、文件魔数、OOXML 包结构、压缩条目与解压比校验；
- 恶意文件保留在 quarantine 并进入失败状态，不晋升原件；
- 原件使用原子 rename 晋升且不可覆盖；若 rename 成功后数据库更新中断，重试必须用 session `expected_sha256` 校验已有原件，一致才恢复，不一致返回 `DOC_ORIGINAL_HASH_MISMATCH` 且不创建 Version/Job；
- complete、abort、任务 cancel/retry 均有幂等或状态保护；聚合修改使用 ETag/If-Match。

### 持久任务和状态一致性

- SQLite 队列提供 lease、heartbeat、retry wait、最终失败、取消请求、人工重试和进程重启后的过期 lease 恢复；
- Worker 在永久解析降级时把版本标为 `QUARANTINED`；意外错误达到最大尝试次数时把版本标为 `FAILED`；普通循环用安全错误码隔离单任务错误并继续处理后续任务，`--once` 遇到任务错误返回非零；
- Version 增加 `CANCELLED` 终态；QUEUED/RETRY_WAIT 取消同步 Version，RUNNING 取消由 Worker 在解析后、产物写入前确认并 acknowledgement；取消或失败后的人工 retry 将 Version 恢复 `PROCESSING`；
- OpenAPI v1 现有 13 条路径，包含 ingestion job 查询、取消与人工重试；
- SQLite schema 升级到 v2，旧 v1 数据库自动补充 Chunk 的 `kind`、`chunking_revision`、`tokenizer_id`；迁移测试通过。

### 契约和解析边界

- Markdown/TXT/上传型 HTML、文本层 PDF、DOCX、PPTX、XLS/XLSX/CSV 使用本地合成 Fixture 验证；
- 扫描 PDF/图片明确返回 `OCR_REQUIRED`/`MINERU_REQUIRED`，不伪装本地解析成功；
- DOCX 原生路径明确记录页映射不可用的质量问题；
- 全部 CanonicalDocument 与 Chunk 均保留定位、checksum 和生产 revision，输出固定 `real_acceptance=false`。
