# 定向读取、游标分页与请求隔离

## 当前代码与本次修复

上传仓库此前已经使用 `LazyCollection`，普通按 ID 读取和更新只加载对应实体，`sync()` 仅比较已加载的实体并保留行级版本校验。本次修复仍会触发整类读取的版本分配和旧文档知识库回查：前者只读取目标文档最新一条版本，后者按目标文档查询会话。文档列表只读取当前页，并为每篇文档加载一个所需版本及其匹配的上传会话；不再将全部版本和会话加载后排序。知识库身份检查也改为按 ID 查询。

`load()` 保留显式集合读取能力，供集合列表、迁移和其他仓库使用；`fetchall()` 本身不等于整租户读取，查询条件和 `LIMIT` 才决定其范围。旧快照迁移仍是一次性的全量维护流程。此次针对上传仓库及文档读取路径的修改，不表示生命周期、治理等其他聚合仓库的全部扫描均已消除。

## 列表协议

文档列表和分片列表（含管理预览）保持数组响应，新增 `X-Next-Cursor` 响应头：

1. 首次请求不传游标，可指定 `limit`；文档上限 100，分片上限 500。
2. 继续请求时将响应头原样作为 `cursor` 参数。空响应头表示扫描结束。
3. 游标记录最后扫描位置；即使权限过滤导致本页为空，只要游标非空，就可继续。游标不授予权限，每页均重新授权。
4. 文档按文档 ID 排序，分片按 `(ordinal, chunk_id)` 排序。游标绑定租户、知识库或版本，以及阅读/预览模式；错误游标返回 400。
5. `offset` 为旧客户端保留，不能与游标混用。前端已改用游标，不再根据返回条数推算偏移。

每页读取至多 `limit + 1` 个原始候选，额外一条用于判断后续是否还有数据。游标避免前页插入或删除造成的偏移跳行，但不是数据库快照：翻页期间新增的较早 ID 不会出现在已翻过的范围，重新刷新可重新列出。

本次没有生产压测或 MySQL `EXPLAIN ANALYZE`，不对吞吐量、延迟或数据库实际扫描行数作结论。JSON 字段过滤、计数、授权检查与其他聚合的读取仍需按真实数据规模评估查询计划和索引。

## 同步路由与前端

当前文档、知识库、搜索、问答及流式问答入口已经是普通 `def`。FastAPI 将完整入口放入线程池，包含知识库查询和生命周期读取；同步 SSE 迭代器也在线程池执行。本次保留这些边界，并用阻塞仓库替身验证事件循环仍能响应异步探针请求；这不是线程池容量或数据库连接池压力测试。

前端保留已有知识库、文档和问答请求序号，并增加分片请求序号、知识库/版本/预览模式检查。切换知识库立即清空旧文档、分片、答案、检索结果、来源、错误和进度；旧响应的正文、错误和 `finally` 均不能修改新选择。重新发起问答也会清空旧引用来源。

验证使用 SQLite、本地模型替身、MySQL SQL 兼容测试仓库和前端延迟 Promise，不依赖外部模型或生产数据库。
