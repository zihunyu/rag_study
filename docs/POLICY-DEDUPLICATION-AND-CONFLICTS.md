# 制度条款去重与冲突检查

## 去重必须保留事实差异

`near_duplicate()` 仍使用配置的三元组 Jaccard 阈值（默认 0.92），但相似度只作为合并条件之一。非完全相同的正文还必须具有相同的结构化数值签名和正文骨架：数值、单位、日期、比较关系、范围及它们出现的位置保留在签名中，其他文字、否定词、适用对象、条件和标点保留在骨架中。无法可靠解析的表达不授权近重复合并。

因此，共同正文很长、只有“15天／30天”不同的两个候选会保留。“15天／十五天”等已知等价形式在达到相似度阈值时可以合并。仅仅语义相近、骨架不同的改写会保留；这是有意选择的保守策略。

正文展示文本和检索文本都必须通过检查，有效期、权限范围、密级和章节上下文也必须一致。相同 checksum 不再是绕过这些检查的理由。每次请求缓存已计算的文本签名，避免对同一正文反复解析；不使用跨请求正文缓存。

## 来源与检查范围

- 相同内容合并为一个搜索结果时，`duplicate_sources` 保留每个来源的文档、版本、分片和定位信息；搜索 API 同步暴露此映射。
- 冲突检查集合保留有权限的重排候选及其重复来源。展示数量、文档和章节配额只限制生成／展示，不删除这个集合中的候选。
- 证据包将未展示的来源保存为 `conflict_context`。生成器只接收命中及父级上下文，验证器接收完整证据包；模型不能引用未提供给生成器的隐藏来源来补救答案。
- 所有来源都参与当前权限复核和运行记录持久化。缓存键包含完整集合以及检索、验证和权限策略版本，因此未引用制度的变更同样会使缓存失效。缓存命中后仍重新验证。

检查范围受检索通道 top-k 和 `rerank_top_k` 限制，不是全知识库扫描；未召回或超出候选上限的文档不在本轮检查范围内。

## 有效期、权威性与冲突处理

1. 只有通过租户、ACL、密级、生命周期、当前版本和有效期检查的证据参与业务判断；过期／非当前版本不会作为现行制度参与检索。响应放行前继续复核完整集合。
2. 检索排名代表相关性，不能代表制度效力。当前检索投影没有治理确认的权威优先级，因此证据组装使用 `authority_rank=0` 表示未确立优先级。不得按检索排名、旧的 rank 数字、新日期或文档自称权威来选出胜者；当前版本与撤回状态仍由已有生命周期规则确定。
3. 确定性验证把引用支持检查与全体证据冲突检查分开。针对答案涉及的对象，它能识别同一适用上下文中不相交的数值约束，以及明确的肯定／否定条款；其他无关属性的差异不会阻断该断言。不同范围字符串或无法结构化的改写交给语义检查判断，不假定字符串不同就一定互斥。
4. 生产模型验证器分别接收 `claims[].evidence`（该断言声明的引用）和 `conflict_evidence`（完整集合），必须独立返回 `conflict_check`。未引用材料不能用来证明引用本身正确；相关、适用范围重叠且未能确立优先级的冲突返回 `CONFLICTING_EVIDENCE`，不返回确定答案或写入已验证答案缓存。

模型验证输出新增必填协议：

```json
{
  "verdicts": [{"verdict": "SUPPORTED", "reason_code": "CITED_SOURCE_SUPPORTS"}],
  "conflict_check": {
    "checked": true,
    "conflicting_evidence_ids": ["E1", "E2"]
  }
}
```

检查完全部提供的证据且未发现相关冲突时，ID 列表为空。省略检查、假值、未知 ID、重复 ID 或只有一个冲突来源均作为模型协议错误处理。模型验证器 revision 已更新为 `conflicts:v2`，确定性验证和缓存策略也已更新；接入自定义模型代理时需同步这一协议。无需数据库迁移。

## 验证边界

新增测试使用合成制度和本地／模拟模型，覆盖高相似度下的数值、日期、金额、否定和范围差异，checksum 误用、来源映射、配额以外候选、未引用冲突、缓存变更、权限复核及模型协议损坏。测试不代表线上文档统计，也不证明能发现任意自然语言冲突或全库所有冲突。

2026-09-06 验证结果：后端回归 730 passed、4 skipped、37 deselected；去重／冲突专项 51 passed；Ruff、Mypy（188 个源码文件）、OpenAPI 快照与 `git diff --check` 通过。4 项本机数据库服务测试和 37 项集成测试未运行，模型调用使用本地替身。新合成用例的 Jaccard 为 0.969072，在阈值 0.92 下两份不同期限制度不会被合并；该数值与原报告样例分别计算。
