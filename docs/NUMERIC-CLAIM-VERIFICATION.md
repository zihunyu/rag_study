# 问答中的数值事实校验

`domain/numeric_facts.py` 将断言及其引用证据分别解析为数值事实，再进行结构化比较。
`application/qa.py` 不再用字符替换或子串包含关系判断数值是否有依据。

## 确定性检查

- 数值使用 `Decimal`。支持中文位值数（十五、二十、一百零五、一万五千）、中文数字年份、常见大写数字、小数、负数、全角字符、规范千位分隔，以及 `1.5万` 等明确的数量级。
- 数值保留单位和币种；百分比与百分点不同。天、小时、分钟等按固定比例转换；日历年、月、工作日分别保留，不假定每年或每月的天数。
- 完整日期先按日历校验，时刻先按时分秒校验，避免拿日期中的局部数字支持其他数值。
- 区分精确值、小于、不超过、大于、不低于。`3至5天`、`3天到5天`、`09:00–17:00` 及完整日期范围作为整体比较，端点不能单独支持一个精确值，也不能跨引用拼出范围。
- 保留数值所在子句的前后对象描述，比较完整对象键；不把其他对象的相同数字当成支持证据。常见引导语和泛指的“设备保修期／保修期”作有限归一化，产品标识符中的内部标点保留。
- 同一对象存在不同数值事实时，不采用“找到一个相同值就通过”的规则。

例如，“退款期限为十五天”与“退款期限为15天”可以通过数值检查；“退款期限为2天”与“退款期限为12天”不能通过。

## 不确定表达与语义复核

此解析器采用有限语法，不替代自然语言语义验证。口语缩写（一百二）、约数、含／不含端点、共享数量级（1至2万元）、不完整或非法日期、暂不支持的时刻表达、对象改写等，返回 `NUMERIC_FACT_REQUIRES_SEMANTIC_REVIEW`。

独立使用 `DeterministicClaimVerifier` 时，该状态不算验证通过。配置 `CompositeClaimVerifier` 时，只有这种不确定状态可以交给独立语义验证器继续判断，最终是否通过取决于语义结果。明确的数字冲突、引用错误、答案未被 claims 覆盖、外链或凭证索取等失败仍提前阻断。混合断言不能用一项不确定结果覆盖另一项明确失败。

数值修复引入结构校验 v3；后续全证据冲突检查将其更新为 `deterministic-claim-verifier:structured-numeric-and-conflicts`，装配中的验证器版本及缓存键随之更新。数值修复本身没有更改 API 返回协议，也不需要数据库迁移；后续模型冲突协议见 `POLICY-DEDUPLICATION-AND-CONFLICTS.md`。

## 回归验证

`backend/tests/test_numeric_facts.py` 覆盖解析、等价形式、子串反例、币种和单位差异、百分比、日期、上下限、时间范围、对象错配及不确定表达。

`backend/tests/test_numeric_claim_verification.py` 覆盖问答结果与引用、确定性／语义验证器串联、失败门禁及多断言冲突。测试使用本地替身，不调用真实模型。
