## 原因与实现

| 原问题 | 本次实现 | 主要位置 |
|---|---|---|
| Markdown 表格按行拆开，表头、单位、条件和数值分离 | 识别完整表格，按完整行分块，保留表头、标题层级及原文位置；相邻正文和步骤保持连贯 | `document_processing/text_parsers.py`、`chunking.py` |
| 文档标题和章节信息不完整；父段落缺少可靠来源映射 | 所有解析器统一携带文档标题；父段落保留全部子块的来源映射；不放行没有完整映射的旧父段落 | `parser_common.py`、`chunking.py`、`application/search.py` |
| 排在后面的有用表格只能参加冲突检查，生成模型看不到；每文档最多三块的多样性规则误伤细节问题 | 增加语义证据选择，从已授权候选及其父段落中选出真正包含答案的资料；允许同一文档多个相关章节参与回答 | `adapters/evidence_selection.py`、`application/evidence.py` |
| 第一次检索不全便停止 | 检查问题各部分是否有资料支持，最多增加一轮、两条补充查询，然后重新选择证据 | `application/evidence.py` |
| 只输入名称就在检索前被要求补充 | 独立名称进入所选知识库查找；资料能确定对象则提供介绍，确有歧义才澄清；未解析指代仍要求补充 | `model_http.py`、`conversation_context.py`、`application/evidence.py` |
| 有依据的部分与无依据的问题一起被拒绝 | 允许只回答得到支持的部分；前端明确显示资料缺项提示 | `model_http.py`、`frontend/src/pages/ChatPage.vue` |
| 无字段名的坐标序列被当成同一个对象的多个冲突数值 | 无法可靠绑定的匿名数字交给独立语义验证；已明确绑定对象的数字不一致仍拒绝 | `domain/numeric_facts.py` |

表格能力覆盖已有统一节点体系。Markdown、HTML 增加结构识别；CSV、XLSX、DOCX 使用已有表格结构并共享新的分块方式；PPTX 增加表头元数据。PDF 等解析器也共享标题及分块逻辑，但本轮没有声称已完成所有扫描件和复杂版式的效果验收。

## 检索与验证约束

- 先沿用混合检索和重排，再做证据选择。`/api/search` 保持原有多样性展示规则；问答从更完整的候选池中选择，不把检索排名当成事实可靠性。
- 选择器使用当前生成模型，只能返回提供给它的候选 ID。伪造 ID、重复 ID、不合法覆盖状态或过多补查计划均拒绝。
- 选择器候选最多约 16000 个保守估算 token，选中最多 8 个来源；生成证据最多约 8000 个 token。保留完整来源，超预算跳过，不将截断文本伪装成完整原文。
- 补查只有一轮、最多两条不同查询，始终使用本轮同一个租户、知识库、索引代次和权限范围。第二次选择仍然缺资料时不会无限循环。
- 父段落扩展重新检查子块、父块、有效版本、生命周期和来源映射。已撤回、删除、跨库或失效版本不能因补查重新进入答案。
- 历史对话只用于理解问题，每轮重新检索。来源校验、独立答案验证以及“验证通过后展示答案”继续生效。
- 模型或检索故障显示失败/重试状态，不用无来源的模型记忆填空。数字规则返回“不确定”代表需要语义验证，不代表自动通过。

接口增加可选兼容字段：`coverage`（`unchecked/sufficient/partial/missing/ambiguous`）、`clarification_question`。RAG run 的证据包另保存实际 `retrieval_queries`，方便区分没有检索、检索未覆盖、资料不全及验证失败。旧问答记录保留默认值，不重新生成历史答案。OpenAPI 快照已更新，本轮不需要新增数据库迁移。

## 旧资料升级与恢复

仅部署代码不会自动改变已经存储的旧分块。本次对 6 份当前已发布、可问答的旧资料做了原文件备份，再通过正常新版本上传、解析、质量检查、复核和发布流程完成升级。原文件 SHA-256 保持一致，旧版本仍可追溯。

工具：`scripts/reprocess_legacy_documents.py`。先生成计划和备份，再应用同一计划：

```powershell
.venv/Scripts/python.exe scripts/reprocess_legacy_documents.py --output artifacts/reprocessing-new-plan
.venv/Scripts/python.exe scripts/reprocess_legacy_documents.py --output artifacts/reprocessing-new-plan --apply
```

- 不带 `--apply` 不提交任何处理任务。已有计划目录不会被新的计划覆盖。
- 只选择当前 `ACTIVE` 且可问答、没有 `token-aware:v3` 分块的文档。已撤回、删除、失败或待复核资料不自动发布。
- 上传和发布使用稳定幂等键；中断后可继续同一 `--apply`。清单采用临时文件原子替换；已发布条目跳过。重复应用本次计划没有增加版本。
- 创建新版本及发布前重新核对生命周期、原活动版本；发布提交 `If-Match` 版本条件。并发撤回或版本变化会停止该文档，要求重新检查。
- 同内容的新版本继承当前有效已发布版本的复核策略。原始文件校验不一致、处理失败或阻断质量问题均记录失败。
- 不直接改数据库生命周期，不清空索引、不清空问答、不建立空库。

本次清单及原文件备份位于 `artifacts/redesign/general-rag-reprocessing/`。6 份均已发布，另 50 份排除资料逐文档比对生命周期完全未变。最终管理统计为 58 份文档、8 份可问答、50 份待处理；其中新增两份为专用验收库中的合成 CSV/Word 文件。

原失败对话仍是历史记录；请刷新网页后发送新问题。旧引用若因版本升级失效，会提示重新生成，不应把旧失败结果当成修复后的新测试。
