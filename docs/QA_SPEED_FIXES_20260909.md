## 已解决的原因与对应改动

| 问题 | 修复后的行为 |
| --- | --- |
| 检索成功后，核验接口立即返回 HTTP 400 | 实际重放确认当前上游不支持配置的 `gpt-5.4-mini`。本地核验模型改为已实测可调用的 `gpt-5.6-sol`，回答模型仍为 `gpt-5.5`，保留生成与核验模型独立的检查。模型清单不能替代真实调用探测。 |
| 排队时间未完整计入超时，重试与条件批次难定位 | 每次 HTTP 调用共用绝对截止时间，额度排队会扣减剩余网络时间；过期后不再发送。取消会传入工作线程并终止在途 HTTP 请求。记录排队、网络、重试、阶段和批次耗时。 |
| 分批后仍有一个特别慢的批次 | 在原批次数与字符上限内均衡分组，例如 17 条从 16+1 调整为 9+8。依据账户剩余额度、占用、等待队列及并发上限选择 1～3 路，最后按原条件编号合并。 |
| 条件不足 16 条时仍把过多事实和条件塞进同一调用 | 同时计算事实与条件负载；合计超过 16 项时，将完整事实/冲突检查与条件检查拆开。Q07 的 15 条事实和 7 条条件保留，拆开后真实复测通过。 |
| 少量条件合并后仍反复超时 | 当前上游改用每批最多 8 条、最多 32 批，保持原来最多 256 条的计数容量。条件批次遇到模型网络超时，只允许再平分一次并重查两半，仍共享原总时限和调用预算；不对额度等待超时或语义失败使用这条重试。 |
| 整题 120 秒先于核验阶段 180 秒结束 | 新增 `QA_FACT_TIMEOUT_SECONDS`，默认 300 秒，统一应用到普通问答、流式问答、会话及验收；单次模型 60 秒、核验阶段 180 秒的限制继续生效。这个调整避免提前中断，不算提速收益。 |
| 总时限到达后，验收只剩 `ProviderTimeout` | 在退出截止时间上下文前保存已产生的问答回执及诊断；保留耗时和稳定错误码。新增“补全后重新核验”的独立耗时行。真实超时复测已保留下运行编号、失败阶段、批次和已完成批次数。 |
| 补写仍只写“按条款执行” | 已标记遗漏的原文条件必须补出具体前提、除外项或限制，不能用笼统引用代替；补写后仍重新执行完整事实、条件和冲突核验。 |
| 补齐一个遗漏，又丢掉先前已满足的条件 | 补写资料同时携带 `covered` 和 `missing` 条件，保留全部相关来源与引文；补写后重新核验所有条件。转引条款按实际相关限制判断，不强迫复述固定套话，也不允许用套话替代具体限制。 |
| 跨型号比较只引用其中一边 | 生成端明确要求比较结论及其事实清单同时引用构成结论的各方资料；针对能否使用某项服务的问题，聚焦被询问型号及相关替代方式，保留实际决策所需条件。 |
| 上游限流仍显示笼统的核验不可用 | 现在明确显示 HTTP 429，核验结果保留安全错误码及状态；旧记录也能根据最后一次 HTTP 调用识别限流。侧边栏已用真实失败记录验证显示。 |
| 无关条件被误判为必须写入回答 | 核验明确检查问题对象、事实对象和条件适用范围；同文件、同级标题或口诀关键词不直接构成适用依据。适用性与解释矛盾时进行有界纠正，不自动改为通过。 |
| 文字问题重复做图片判断和资料选择 | 在已验证裁图信息完整时，将图表依赖判断并入原资料选择调用。仅明确无关的裁图可排除；显式图号引用、不确定内容、潜在冲突与跨图关系继续检查。补充检索发现新引用时重新打开此前排除的裁图。 |

| 相同问题每次都重新检索、生成和核验 | 新增已验证完整结果的精确复用，绑定问题、会话解析后的问题、阅读范围、完整知识库发布状态、内容、权限、有效期、模型和规则配置。返回前重新检查发布状态及授权，生成本次运行的新引用。 |

| 管理员只能看到“核验未完成” | 页面区分模型不受支持、HTTP 拒绝、额度等待超时、核验超时、条件容量不足、遗漏条件、事实不受原文支持及引用不完整，并展示失败步骤、批次、运行编号和耗时。未通过核验的正文继续隐藏。 |
| 验收页面轮询与执行发生 MySQL 死锁 | 恢复任务先读过期候选，再按固定顺序锁运行记录、重查租约并更新尝试记录；避免原先先锁尝试记录、再锁运行记录的反向顺序。 |

## 保留的准确性约束

- MinerU 的正文、标题、顺序和结构继续保留；预计算条件引文、原文哈希、节点关联仅增加可重建的元数据。
- 不把全部同级标题当作可靠章节终止边界，不按标题截掉后续分类；保留邻接与显式引用上下文。
- 没有相关裁图不调用图片模型，不把整页视觉识别加回 MinerU 路径。存在图表节点却缺少裁图时，标记覆盖缺口。
- 全部授权候选资料仍进入一次完整冲突检查，包括未被答案引用的资料；全部条件均须返回核验结果，任一批失败不能发布部分核验结果。
- 新增未引用的冲突文件、撤回、改版、权限变化、有效时间变化、模型或规则变化都能阻止旧答案复用。精确结果缓存异常时回到正常流程。
- 验收运行绕过完整答案缓存；权限失效仍会暂停运行。没有延长登录有效期，也没有绕过最终授权检查。

## 运行配置

本地 `config/.env` 使用 `VERIFIER_MODEL=gpt-5.6-sol`、`VERIFIER_TIMEOUT_SECONDS=60`、`VERIFIER_CONDITION_BATCH_SIZE=8`、`VERIFIER_MAX_CONDITION_BATCHES=32`。总核验期限继续为 180 秒，具体问题总时限默认 300 秒，账户并发上限 3、每分钟 token 上限 200,000 保持不变。

优化开关为 `VERIFIER_CONDITION_PARALLELISM`（1～3）、`QA_VISUAL_DEPENDENCY_PLANNING`、`QA_EXACT_RESULT_CACHE_ENABLED`。设置并行为 1、关闭后两个开关可回到串行及无新增复用的路径；不会关闭事实、条件、冲突和权限核验。源码中的配置默认值及示例已列出这些开关。
