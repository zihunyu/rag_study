# WORKER-01：正在运行的解析任务取消

Worker 将租约守卫的取消检查传给 `ParserRouterPort.parse(..., cancel_check=...)`，
并在整个入库任务内建立取消上下文。守卫以不超过 250 ms 的间隔刷新队列状态并续租；
解析器的检查只读取本地线程事件，不在每次检查时连接数据库。小于 750 ms 的租约仍按
租期三分之一刷新。增加的队列开销约为每个活动任务每秒四次心跳，不是每个分片四次。

本地原生解析格式和生产配置中的原生解析器均通过隔离进程执行。父进程每 100 ms 检查取消
或租约失效；收到信号后主动 terminate，必要时 kill，并 join、关闭管道、清理临时目录。
不再等待解析函数自然返回。解析器的超时、CPU 与输出限制继续生效。取消和租约失效
直接传播，不会被当作 OCR_REQUIRED 等可降级解析错误再启动备用解析。

MinerU 的请求提交、签名上传、状态查询和结果下载在 Worker 取消上下文内使用可取消的
异步 HTTP。同步 Worker 等待期间检查信号，取消后等待请求清理完成，不留下后台请求线程。
签名上传仍携带准确 Content-Length 且不带 Bearer；结果下载继续限制 URL、跳转次数和大小。
轮询间隔拆成可中断等待；结果校验、节点转换和分块循环也检查信号。

取消仍以任务及版本的 CANCELLED 为本地完成状态；写入前的租约检查和数据库 fence
继续保留。检测到租约失效后，旧 Worker 停止处理，不回写任务结果、分片或 Provider 检查点。
取消不计为 Provider 故障，也不触发自动重试；Token 占用正常释放。

远端已经受理的 MinerU 任务可能继续执行。本次实现取消的是本地等待和网络操作，
现有 Transport 契约没有远端取消 API，因此不能宣称云端任务已终止或停止计费。
提交途中取消保留 UNKNOWN_OUTCOME，后续不得盲目重新提交，仍需人工对账；已知 batch_id
会保留用于对账。轮询时取消保留 SUBMITTED 及 CANCEL_REQUESTED 中断标记。
租约失效保留最后已保存的检查点，旧持有者不再修改它。

自定义 `ParserRouterPort` 实现必须接受并遵守 cancel_check；需要执行阻塞原生代码的扩展
应使用进程边界，需要协作式 I/O 的扩展应检查取消上下文。任意忽略取消的第三方 Python
函数无法由线程安全地强制停止。当前默认 Local 和 Production 解析链路已经接入。

回归测试位于 `backend/tests/test_ingestion_cancellation.py`：启动真实 spawn 子进程并让其
持续阻塞，通过取消 API 或注入租约失效，要求 Worker 在三秒内退出；确认子进程结束、
临时目录清理、未保存 canonical artifact、分片数量为零。另有 HTTP 等待取消及清理、
签名上传契约、结果下载边界、轮询中断、未知提交结果不重复提交的离线测试。
三秒是合成测试的门槛，不是生产延迟承诺；未调用真实 MinerU 或其他计费模型。
