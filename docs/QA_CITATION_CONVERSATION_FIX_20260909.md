## 1. 引用遗漏只修引用，再执行完整核验

此前失败运行 `01a0848e-1cf6-7519-b8b4-bc33215b70d0` 的事实表格已有来源支持，但导语缺少引用，核验以 `uncited_factual_intro` 拒绝整份回答。

现在仅在已有事实检查通过、整体事实覆盖通过、冲突检查完成且没有冲突时，允许对引用遗漏进行一次有界修复。模型只能提交“给哪一行添加哪些既有事实对应的引用”，不能重写正文、增删事实或引入新来源。程序再次验证原文、事实清单与来源集合保持不变。

修复后重新运行完整核验，包括全部事实、回答引用、全证据池冲突检查和全部候选条件。仍然失败、超时或出现冲突时，不发布草稿。既有的一次条件补写与新的一次引用补齐共用原请求截止时间和调用预算，不形成无限重试。若引用问题最终未解决，记录为系统核验失败，不再错误地归为知识库资料不足。

生成提示也明确要求：涉及分类、数量、机制或范围的导语需要来源；纯排版说明不应被当成新事实。

## 2. 一份资料不完整，不等于合并后的资料仍不完整

条件批次现在携带条件所在来源的原文，以及回答实际引用的其他来源原文。核验可以实际检查其他来源是否补齐了同一主题、同一范围的缺失部分。

若其他已提供且被引用的资料确实补齐了局部摘录，局部范围警告对合并回答记为 `not_applicable`，并说明来源间的关系。若互补资料不存在、主题不匹配，或回答把局部资料说成完整资料，仍会拒绝。业务限制、流程分支和真实缺口不会被这条规则免除。

本轮真实回归还发现了输出约定问题：模型曾将“其他来源补齐了内容”写成 `covered`，而回答并未陈述该局部警告，严格的原文见证校验因此拒绝。最终 v22 明确要求这种情况使用 `not_applicable`。没有放松 `covered` 必须有真实回答原文的校验。

生产逻辑没有按药物名称或医学分类写分支；提示中的医疗专用示例已替换成通用的主题、关系、范围和来源规则。设备目录、合同及政策案例用于验证同一流程。

## 3. 会话入口失败保留具体原因

会话问题解析发生在知识检索之前。该步骤的限流、超时等异常，现在也会保存结构化结果：失败阶段、稳定错误码、会话轮次编号、可确认的 HTTP 状态以及阶段耗时。

界面区分真实上游 429、本地单次请求令牌预算超限、排队或网络超时、解析结果无效等情况。发生在解析阶段的错误明确说明尚未进入检索。没有问答运行时使用真实会话轮次编号，不伪造问答运行编号，也不展示原始异常中的敏感内容。历史上只有 `ProviderRateLimited` 类名的消息显示“限流或额度限制”，不凭类名断言一定是 HTTP 429。

只有紧接上一条已回答问题、原问题与已确认解析结果完全相同、且没有指代或追问特征的重复提问，才复用既有解析。新的问题和有指代的追问继续走原解析流程。这不是针对药物或某类名词的跳过规则。
