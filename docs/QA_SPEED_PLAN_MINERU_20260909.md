# 基于 MinerU 正文与裁图分工的问答提速方案

2026-09-09。本文保留修复前的核查依据与实施方案。后续代码改动、真实对照结果和仍待完成的验收见 `docs/QA_SPEED_FIXES_20260909.md`；以下模型配置与观察值属于当时基线，不代表当前运行配置。

## 方案的依据

用户确定的处理规则保持不变：所有实际经过 MinerU 的 PDF、扫描 PDF、DOC、PPT、图片，先保存 MinerU 的正文、标题与结构；图片模型只补充插图、图表裁图；没有相关裁图时不调用图片模型。当前代码还包括 `table` 类型的表格裁图，不处理正文、公式附带的裁图，也不在这条路径上整页渲染回退。

本次核查结果：

- 新上传的统一解析路径为 `visual-document-v6:provider-layout-first`，按基础解析器能力分派。五种路由、MinerU 结构转换和视觉供应商异常相关的 **41 项回归通过**，没有新增外部模型调用。
- 示例 PDF 当前发布的是第 7 版 `01a08350-9f51-78ee-9aec-07fa89289c62`，状态 `SERVING`；第 5 版已被替代。第 7 版使用已采用同一 PDF 分工的 `pdf-layout-first` 修订，不是旧的整页视觉解析。
- 当前第 7 版保存 **79 个标题、1639 段正文、1 张插图**。这张插图位于第 12 页，有独立来源、版本和裁图标识。
- 79 个标题的 `heading_level` 目前全部为 2，不能把“已经保留标题”理解为“已准确还原多级目录”。例如“抗抑郁药”和下一项“2.抑制 NE 再摄取”标为同级，只取第一个标题段会漏掉后续内容。
- 当前配置：回答模型 `gpt-5.5`，答案核验模型 `gpt-5.4-mini`，图片识别及图片复核均为 `gpt-5.5`；账户并发上限 3、每分钟 token 额度 200,000。

因此，旧版“图片复查耗时 54～82 秒”和“85 条条件核验可提速 55%”只能作为历史证据，不能直接当作新版的收益，也不能把旧耗时减去图片时间就宣布新版速度。

## 新版已有请求暴露的问题

发现一条使用第 7 版的请求：“镇静催眠药有哪些”，运行编号 `01a083aa-3146-7aa4-b9b9-9f4a9015716f`。

| 环节 | 观察值 |
| --- | ---: |
| 上下文理解与问题判断 | 7.3 秒 |
| 向量与排序 | 3.5 秒 |
| 唯一插图的问答复查 | 7.4 秒，最后返回不相关 |
| 选择证据 | 6.0 秒 |
| 生成答案 | 16.2 秒 |
| 基础答案核验 | 0.8 秒后 HTTP 400 |
| 整轮 | 43.3 秒，**失败，不能计为成功响应耗时** |

该次证据包为 45 个片段、17 条候选条件。统计来自实际会话和同一时间窗的模型调用流水。它说明：

1. 入库时不再把正文交给图片模型，但问答端仍可能先调用图片模型判断一张图是否相关。
2. 本次生成需要约 16 秒；完整核验尚未成功，当前没有足够数据确定新版正常问答的耗时基线。
3. 条件数可能已明显变化；17 条只需要两批，原来六批条件并行的收益不能照搬。
4. `MODEL_PROVIDER_HTTP_ERROR` 目前被归为通用核验协议错误。需要保存安全的 HTTP 状态和失败阶段，区分接口拒绝、模型输出格式及引用校验；不能假定 400 是本地条件容量导致的。

## 目标和边界

优化原文的重复读取、重复计算、重复请求和串行等待；保持已发布知识、必要事实、条件、引用、权限隔离和完整授权候选池的冲突检查。

“完全不损耗”作为**零准确性退化的上线门槛**：必要事实不能减少，条件与例外不能遗漏，冲突不能漏报，错误引用不能通过，权限和版本不能混用。少量测试不能保证任意未来问题都正确，因此不以单次回答通过宣称普遍无损。

本轮先不采用缩小检索 top-k、按标题硬截断、摘要替代原文、减少核验项或提前展示未验证草稿。全书总结和跨文件综合继续按用户选择的资料范围执行。

## 一、先建立新版成功基线并补齐耗时记录

先定位本次核验接口 HTTP 400，保留可用的状态码、模型、阶段和运行编号；敏感响应与凭据不进入普通用户界面。接口恢复后，以同一已发布版本和同一模型配置重新运行原三个问题及代表性的文字、图表、跨文件问题。

成功和失败都记录：检索、图片补充、生成、条件补全、基础核验、各条件批次、最终授权的耗时；每次调用的排队/网络时间、输入输出 token、重试次数、缓存命中原因。

同时修正现有队列时间预算传递：账户额度等待结束后，HTTP 请求只能使用剩余时间；整个请求、核验阶段和单批截止时间层层约束。失败后停止未开始任务，在途请求保留可取消、可追踪的结束过程。

交付：可以直接回答“这题为什么花了多少秒”的逐运行记录，以及新版成功请求的中位数和 P95。

## 二、把解析结构用于问答准备，正文仍保留原样

入库时在原文之外建立可重建的辅助信息：

- 原始节点、标题顺序、页码/幻灯片/位置、来源区间与内容哈希。
- 正文和裁图的实际关联，图注、正文明确引用、表格的表头/单位/脚注及跨页续表关系。
- 条件候选的原文锚点、所在段落和上下文；预先计算候选，不预先决定其对未来问题是否适用。
- 可用于复用判断的文档、解析器、图片复核与索引修订标识。

辅助信息不能改写 MinerU 原文。标题层级不可靠的地方保留原始层级，另记录边界不确定；利用相邻节点、原始顺序、表格连续性和显式引用补足上下文。第一阶段只改组织、定位和重复数据传输，不减少已有授权候选证据。

对纯正文问题，直接使用已经保存并发布的 MinerU 文本。对涉及图表的问题，再加入相应的裁图证据。没有裁图不代表原文未解析，也不代表可以声称图表内容已确认。

交付：正文与插图不会因为共用同一文档或页面而被整批送进图片复查；章节导航不会把分类后半部分、跨页表格或例外条件截掉。

## 三、让问答端也满足“没有相关裁图就零图片调用”

新增明确的本轮图片清单，依据已保存的来源关系制定，不能只看问题里有没有“图”字：

| 情况 | 行为 |
| --- | --- |
| 当前有效证据没有相关裁图，且图表范围无未解决缺口 | 图片模型调用数为 0，使用 MinerU 正文进入原有问答核验 |
| 表格、曲线、图中数值、流程分支等需要裁图支持 | 保留原图补充和独立复核，再加入相应证据 |
| 正文有明确图表引用或跨图关系 | 沿引用关系加入必要裁图，不因正文已命中而略过 |
| 关联或覆盖范围不能确定 | 保留补充检索/复查；仍不能确认时明确资料缺口，不将不确定当作无图 |
| MinerU 有图表节点但没有可用裁图 | 遵循用户规则不调用图片模型、不整页回退；记录图表缺口，避免完整覆盖声明 |

图片之间可以在预算允许时并行；单张图的“识别→独立复核”顺序和跨图最终整合继续保留。对当前只有一张插图的 PDF，优先消除无关调用、复用已确认结果，图片并行本身不是主要收益来源。

本次观察的 7.4 秒是一个可调查的浪费点，不是所有文字问题都能固定减少 7.4 秒的承诺。

## 四、优先消除条件误判返工，再开放预算感知的并行

上一轮冻结输入中，串行和并行对同一问题分别判缺 6 条和 12 条，涉及其他主题。这一核验语义问题不能靠 MinerU 路由调整自动解决。

每个条件要有可核对的适用依据：针对用户问题或答案中的哪项事实、原文对象、适用范围和例外。仅仅在同一文件或标题附近不构成适用依据；反过来，也不能仅因答案未提及就判为不适用。适用性与解释矛盾时进入有界纠正，不触发无依据的答案补全，更不能直接改成通过。

在归属专项验收通过后：

1. 保持原基础事实、引用、完整授权候选池冲突核验。
2. 按现有规则拆分全部条件；必要原文、编号、全局流程节点上下文均保留。
3. 依据当前账户剩余 token、排队和调用预算决定 1～3 路并发。17 条和 93 条使用相应的实际批次数，不固定开三路。
4. 全部完成后按原编号合并，任一批不合格不能放行；补全答案后仍检查新答案。
5. 同一请求中完全相同的子任务可以合并等待，但必须连同问题、答案、证据、规则和模型配置一起比对，答案发生变化就不能复用旧核验。

历史实验支持“这种调度有潜力”，尚不构成新版无损上线证明。账户 200,000 token/min 的限额必须保留，不通过无限扩大并发来制造表面速度。

## 五、让重复提问真正复用已验证结果

当前答案缓存命中发生在检索和图片复查之后，且仍会重新核验。新增完整结果与核验凭据的精确缓存，尽量在昂贵工作前确认是否可复用。

缓存绑定至少包括：

- 问题、解析后的会话上下文、知识库/指定文件、阅读方式。
- 当前完整发布快照及检索修订，包含未引用但可能构成冲突的资料状态。
- 文档版本、正文/裁图内容、解析与图片审核修订。
- 生成及核验模型、提示词、规则和相关配置。
- 租户、用户、权限修订和资料有效时间。

新增或发布冲突文档、撤销文件、权限改变、模型规则升级都必须失效；不能只检查答案曾引用的那几份文件。返回前重查当前授权、发布快照与来源有效性，并生成当前运行可访问的引用。普通语义相似度不用于直接复用答案。

单图和单次模型输入完全相同也可建立精确缓存；不完整、待复核的图不能作为已核验事实缓存复用。缓存中保留原回答的覆盖缺口，不把部分覆盖变成完整覆盖。

这项主要改善重复问题；首次问题仍要完成正常检索、生成和核验。命中条件变化时恢复完整流程。

## 验收和实施顺序

| 阶段 | 实际交付 | 通过条件 |
| --- | --- | --- |
| 1. 可测、可成功 | 修复 HTTP 400；每个请求和批次耗时、等待、重试可定位；得到新版成功基线 | 不能把快速失败计作提速；基线固定发布版本、模型和配置 |
| 2. 正文与裁图协作 | 原文锚点与依赖清单；正文问题零无关视觉调用；精确图片复用 | 正文、分类后续项、表格脚注、跨页内容、图表与显式引用覆盖不减少 |
| 3. 可靠核验与调度 | 条件归属修正、剩余时间预算、1～3 路并行 | 条件/冲突/引用零新增漏判，误报和系统失败率不升高 |
| 4. 精确结果缓存 | 热问题复用；发布、权限、时间、规则变更自动失效 | 缓存与非缓存的事实、条件和来源一致；撤权及新冲突均能阻止旧答案复用 |

数据集使用现有 24 题、原三个长资料问题，并补齐以下新版专用案例：五类 MinerU 路由的无裁图文件、扫描正文、图表专有事实、正文没有“图”字但必须查图、无裁图的图表缺口、同级标题导致的分类后续内容、跨页表格脚注、跨文件冲突、问题外条件、图片更新、权限撤销和新增冲突文件后的缓存失效。

每一项优化独立比较，避免同时改变解析、模型与调度：

1. 固定当前发布快照，先同配置重复运行，识别基线模型自身的判定波动。
2. 同输入进行优化前后对照；初次请求与缓存命中分开，单用户与额度繁忙分开。
3. 比较必要事实、数字单位、否定/例外、来源与版本、跨文件冲突、隔离、覆盖缺口。事实评测以人工确认的预期事实和来源为准，不只看系统自己的 `verified=true`。
4. 比较成功答案的完整响应时间、P50/P95、失败率、调用数和成本；保留所有失败样本。重放同样请求不等于测试多种不同问题。
5. 任何事实退化、必要条件遗漏、错误引用或权限失效都不进入默认模式；保留可回退的原流程。

先以新版成功基线为参照，设定**首次正文问答整体耗时减少约 30%、完全相同条件的重复提问减少至少 80%**作为工程目标，而非已验证收益；全书综述及图表问题单独设目标。只有达到准确性门槛后才判断速度是否达标。

本方案本次完成的是代码核查、当前发布版本和请求流水只读分析及 41 项本地回归，未修改运行中的问答流程。核查数据保存在 `artifacts/qa-speed-plan-20260909/current-basis.json` 和 `new-version-observed-run.json`；9 月 8 日的旧版评测保留在 `docs/QA_LATENCY_EVALUATION_20260908.md`，两份基线不混用。
