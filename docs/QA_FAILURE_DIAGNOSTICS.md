# 问答核验失败修复与诊断

2026-09-08，针对同库三文件检索成功、最终返回
`VERIFIER_CONDITION_WITNESS_INVALID` 的问题。

## 复现与原因

原请求记录见 `docs/CROSS_DOCUMENT_QA_CHECK.md`。用该次已保存的合成资料证据重新调用生成及
独立核验，复现了相同错误，并保留了模型实际返回值。

1. 答案正确包含保修三年及起算时间、常温 420 W / 低温 390 W、三十天退款及原路退回。
2. 核验模型将 K3“本文件描述一个虚构产品，仅用于软件链路验收”标为 `covered`，但引用的是
   只说明保修期限的表格行；该段并没有表达这条条件，校验因此拒绝。
3. K2 上门维修预约及时段被模型合理地判为 `not_applicable`，本地规则却因标题中的共同产品名
   及“时间”等词强制改判为缺失。中文双字切分还产生了“间是”这样的无效主题匹配。
4. 另一条真实核验响应把未涉及的条件标为 `covered`，却返回空的 `answer_quote`。只调整相关性
   提示不能确保每次响应都符合协议，因此需要有上限的协议纠正。

## 修改

- 条件相关性按具体规则正文判断，短缺省限制保留前一句上下文。共同标题、产品名或泛化的
  问句用语不再自动证明两个规则相关。仍保留独立模型的语义核验，以及针对相关维修限制、
  并列前提、否定例外、流程分支和图关系覆盖缺口的校验。
- 核验提示明确区分 `covered`、`missing`、`not_applicable`，增加完整 JSON 示例；资料用途
  说明是否适用，取决于具体问题与答案是否涉及其范围。
- 条件协议错误，以及缺少必需冲突检查字段时，允许一次完整重核验，携带具体条件编号或
  字段名和失败原因；两次共用原核验超时。
  每次均重新核对所有事实、完整正文、引用、冲突及条件，错误状态不会直接在本地改成通过。
  第二次仍不合规则保留失败。既有低成本真实验收执行器显式关闭此纠正，保持单次调用策略。
- 核验 revision 升级，避免沿用旧核验规则的答案缓存。
- 失败的私有 EvidencePackage 新增 `diagnostics`，沿用 SQLite/MySQL 的 JSON 存储，无需新增表。
  保存阶段、详细错误、生成草稿以及模型请求/响应快照。请求之间通过 ContextVar 隔离；模型
  快照最多 8 条、512,000 字符，超限明确标记截断并保留较新的调用。
- 只保存对话请求内容及响应的 choices/usage，不收集 HTTP URL、请求头或认证密钥。诊断正文
  不进入 AskResult、会话接口或普通日志，只能由具有本地数据库访问权限的维护人员导出。
- 页面对于核验协议失败显示明确原因，并在“技术详情”中展示运行编号和已有错误码；即便会话
  状态为 completed、没有 turn.error_code，也能定位这次问答。未核验草稿继续隐藏。

## 排查命令

默认只输出状态、模型版本、失败阶段、条件编号、证据编号和详细原因，不输出资料正文：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/inspect_rag_run.py --run-id <运行编号>
```

重放已记录的条件响应，只执行本地校验，不调用模型、不发布回答：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/inspect_rag_run.py --run-id <运行编号> --replay-conditions
```

确需查看模型具体输入输出时，可导出到本地维护目录：

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts/inspect_rag_run.py --run-id <运行编号> --include-content --output artifacts/qa-diagnostics/run.json
```

该导出包含私有问题、资料和未发布草稿，应按原资料权限管理。旧运行没有这项诊断记录时返回
`diagnostics_available=false`，不能恢复当时未保存的模型响应；截断记录也不会声称可以完整重放。

## 24 题实测后补充

执行与逐题记录见 [合成资料 24 题真实验收](SYNTHETIC_QA_V1_LIVE_ACCEPTANCE_20260908.md)。

- 条件库存使用实际展示的原文，排除检索时附加的重复标题和章节路径。跨文件的“按保修条款
  执行”等引用关系仍交给语义核验，只从本地否定词／并列词检查中排除纯引用子句。
- 核验模型可返回答案中已有段落的 `answer_span_id`，由服务端获取原样文字，避免模型改写
  引文导致 `quote_not_in_answer`。相关性增加 `applicable` 布尔值，字段相互矛盾时重新核验。
- 只有显式算式、原文中已有操作数且计算正确的派生值，才可以进入独立语义核验；仍需核对
  产品、条件、单位与来源。裸猜数字、错误运算及未提供的操作数继续拦截。
- 已选资料范围中的“两种设备”等明确属性问题先检索；同一对象的不同政策选择两份证据，
  交给冲突核验，不能要求用户先挑选自己偏好的政策。
- 冲突拒答也保存私有诊断与冲突证据编号。缺少 `conflict_check` 的响应不能凭草稿内容推断
  为成功，必须完成整个核验响应后才能得出最终状态。
- 正向冲突结论必须附两条不同的逐字原文及同一适用对象／条件下不兼容的理由。重复的父级
  和子级内容不能仅凭两个证据编号构成冲突；缺少或伪造引文进入有上限的完整协议纠正，
  不会在本地直接把冲突改为无冲突。仅查询申请材料不等于询问完整维修资格及预约流程。
- 阅读覆盖与引用章节数量分别报告。已读但未引用的章节记录在 `uncited_sections`，不再
  自动变成阅读缺口；实际未读、不可用或遗漏关键条件仍保持覆盖不完整。
- CSV 父级来源的公开定位按真实来源片段合并同工作表、同列且连续的行范围，不再沿用第一行
  标注。对不连续或不同工作表的片段不猜测一个连续范围；来源内部元数据仍不公开。
